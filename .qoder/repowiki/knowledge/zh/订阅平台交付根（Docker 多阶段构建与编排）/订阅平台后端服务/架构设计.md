采用分层装配模式：`cmd/server/main.go` 作为唯一入口，按固定顺序初始化日志、SQLite 存储（执行 `migrations/` 中嵌入的 SQL 迁移脚本）、配置服务、用户服务与版本指针自检，再调用 `internal/server` 装配完整或应急两种 HTTP 服务；各业务域（认证、订阅平台、管理员运维、支撑服务）以独立包形式被 server 路由层注入，基础设施层（config/store/response/ratelimit/oidc/slug）为所有上层共享依赖。启动时通过 `emergency.Detect` 判定是否进入仅暴露状态/重置端点的应急模式，并在信号中断时优雅退出；访问日志由 `internal/cron` 定时清理，形成“入口→基础设施→业务域→HTTP路由”的单向依赖链。前端构建产物通过 `web/web.go` 的 Go embed 一并打包进单二进制。
