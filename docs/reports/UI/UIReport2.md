# VPN 订阅管理系统 UI / UX 深度研究与改进方案（UIReport2）

> **文档定位：** 本报告在 [UIReport1.md](UIReport1.md) 基础上继续研究当前项目的 UI / UX。依据为 2026-08-28 的 `Design2.md`、`Design2-UI.md`、前端源码，以及隔离测试实例中的完整基础模式浏览器走查。本文只记录事实、改进候选与验收口径，不改变产品功能、权限模型或后端契约，也不是已批准的 Design / Build 文档。
>
> **变更边界：** 本轮没有改动代码、设计文档、配置或现有报告，只新增本文。导航分组、主色调整、设置页承载方式与手机复杂表单载体均涉及设计取舍，继续列为待用户确认项。
>
> **结论先行：** UIReport1 的总体方向成立，但第三轮有数据实机核验改变了优先顺序。第一优先级不是视觉润色，而是恢复界面对系统状态和操作结果的可信度：装配器切换类型后会保留上一类型的旧预览；非应急状态直接访问 `/emergency` 会显示“正常服务已暂停”和“未知原因”；无 Token 的重置页仍可输入密码；OIDC 回调仍暴露 `exchange_failed`。第二优先级是手机任务可完成性：大量控件实际高度只有 16、22、24 或 32px，节点表单的 UUID 输入区在 390px 下几乎不可用，危险操作与普通操作紧邻。第三优先级才是信息架构、页面骨架和完整配色 Token。建议按“可信状态 → 手机可操作 → 任务连续性 → 视觉系统”的顺序推进。

## 一、研究目标、范围与方法

### 1.1 本轮目标

- 以真实基础模式用户旅程核验全部可达界面，不只确认路由存在。
- 同时覆盖空数据、有数据、管理员、普通用户、异常恢复、桌面、平板和手机状态。
- 打开并检查页面中的 Tabs、Dropdown、Modal、Drawer、确认框、复制反馈、表单校验、版本预览与装配步骤。
- 找出会让用户误判状态、丢失任务上下文或无法在手机完成操作的问题。
- 在不更换 Vue 3、Ant Design Vue 与 Tailwind CSS 的前提下，给出完整的体验与配色改进方案。

### 1.2 范围边界

**包含：**

- Setup、认证、普通用户、基础模式管理端、动态版本页和装配内嵌视图。
- 空态、加载态、有数据态、错误态、确认态与部分成功反馈。
- 信息架构、页面层级、交互反馈、中文文案、响应式、触控尺度、可访问名称和视觉配色。

**不包含：**

- 高级模式中的用户组、Xray 实例、独立账号和对账业务内容；本轮只验证基础模式下的显隐与深链守卫。
- 真实 OIDC、SMTP、验证码、邮件送达、外部客户端唤起和正式文件导入。
- 删除数据、确认生成新版本、刷新真实 Token、修改密码等会造成不必要副作用的最终提交。
- 后端算法、数据库一致性、权限模型或接口安全性的重新设计。

- **A：浏览器连续旅程。** 实际完成导航、登录、切换、打开、取消、复制或预览等连续操作。

- **C：浏览器边界状态 + 源码/设计。** 外部系统、动态邮件或高级模式限制下，以实际入口和静态契约补齐。

## 三、第三轮关键结论

### 3.1 当前产品不是“页面不完整”，而是“状态可信度不足”

当前基础模式的页面和 API 覆盖相当完整，桌面与手机也多数具备双态列表。真正阻碍体验的不是缺少入口，而是用户无法始终相信屏幕表达的状态：

1. 切换装配类型后，预览继续显示上一个类型的内容。
2. 通用节点订阅仍显示“未选择规则素材池或手动规则，将生成空规则”的无关警告。
3. 非应急状态访问应急页，被告知正常服务已暂停。
4. 无重置 Token 时仍出现密码表单。
5. OIDC 回调错误以内部 key 代替用户可理解的恢复状态。

这些问题会直接削弱管理员对“我将生成什么”“系统当前是否正常”的信任，优先级高于圆角、阴影或插图。

### 3.2 基础模式主任务链已存在，但缺少连续上下文

浏览器实测能从装配缺失条件跳到节点或订阅管理，这证明现有页面已经具备串联基础。问题是跳转后的目标页没有来源提示，也没有“完成后返回装配”；装配类型、当前步骤和已填写状态没有成为可见的任务上下文。

推荐使用轻量 `ContextBar`，不新增强制向导：

```text
正在完成：生成「通用节点订阅」
缺少：至少一个可用节点
[添加节点]  [返回装配]  已保留：目标平台、已填头部、当前步骤
```

### 3.3 手机不是简单的“卡片化”问题

390×844 下，多数列表确实切换为卡片且没有明显整体横向滚动，这是优点。但实测控件高度大量低于推荐触控尺度：

- 顶栏账户按钮约 24px，高度不足。
- 主题 Switch 约 16px，高度严重不足。
- 多数普通按钮约 32px。
- 卡片行操作约 24px，删除按钮与编辑按钮紧邻。
- 装配 Tabs 约 22px 高。
- 节点弹窗内 Switch 约 22px，文本框约 29–31px。

用户页三个平台的“一键导入 / 复制链接 / 刷新链接”均为 32px 高；管理员卡片中的“编辑 / 删除”只有 24px。手机端当前是“视觉上能装下”，不是“手指可靠操作”。

### 3.4 视觉系统缺少完整 Token，暗色层级尤其不稳定

浅色主题由白色侧栏、白色 Header、浅灰页面和白色内容容器构成，整体干净但缺乏辨识度。暗色实测则出现四种未协调表面：

- 页面 Layout：`rgb(0, 0, 0)`。
- 侧栏与 AntD 表格：`rgb(20, 20, 20)`。
- Header 与内容容器：`rgb(31, 41, 55)`。
- 主按钮：浅色 `#1677FF`，暗色算法后约 `rgb(22, 104, 220)`。

大块纯黑与蓝灰内容容器形成明显断层，表格又回到 AntD 黑灰，视觉上像三套暗色系统叠加。当前只配置 `colorPrimary`，Tailwind `gray-*` 与 AntD 算法没有共享表面 Token，这是根因。

## 四、最高优先级问题清单

### 4.1 P0：可信状态与任务完成

| 编号 | 浏览器事实 | 用户风险 | 改进方案 | 验收标准 |
|------|------------|----------|----------|----------|
| UX2-P0-01 | 从 SR 节点装配切到 `generic-subs` 后，预览仍显示 `STATUS / REMARKS` 和上一类型 URI；手动刷新后才变正确 | 用户可能依据错误预览确认生成，破坏所见即所得 | 任何影响产物的字段或类型变化都将预览标记为 `stale` 并隐藏旧正文；提供“内容已变化，请重新预览”状态，禁止以旧预览确认生成 | 类型/目标/节点/规则/覆盖层任一变化后旧预览不可继续作为当前预览；确认按钮禁用直到成功刷新 |
| UX2-P0-02 | 通用节点与 SR 节点装配显示“未选择规则素材池…将生成空规则” | 无关警告误导用户，以为节点订阅缺少规则 | 仅 `clash-yaml` 与 `sr-conf` 渲染规则类警告；按 target syntax 过滤 warnings | 两种节点订阅不出现规则素材警告 |
| UX2-P0-03 | 非应急状态直接访问 `/emergency` 仍显示“正常服务已暂停”和“未知原因” | 用户误判服务故障，并被引导寻找操作码 | 前端先读取权威应急状态；未启用时显示普通 Result“当前未处于应急恢复模式”并返回登录/首页，不展示操作码表单 | 正常状态下页面不出现“服务暂停”、未知原因或操作码输入 |
| UX2-P0-04 | `/reset` 无 Token 仍显示完整密码表单 | 用户输入密码后才知道链接无效 | 页面初始化先判定 token；缺失、过期、已使用分别显示 Result；不渲染密码字段 | 三类无效状态均无密码输入和提交按钮 |
| UX2-P0-05 | OIDC 回调失败回到登录页并直接显示 `exchange_failed` | 暴露内部枚举，无恢复路径 | 映射为用户可读状态；提供重新 OIDC、本地登录、联系管理员三类可用恢复动作 | 页面不出现内部 key，至少一个恢复动作始终可用 |
| UX2-P0-06 | 装配前置条件跳到节点/订阅后没有来源提示或返回路径 | 用户完成依赖后丢失原任务 | `ContextBar` 保存 `tab`、目标对象、步骤和必要表单草稿；补完后一次操作返回 | 补节点/订阅后最多一次操作回到原装配类型与步骤 |
| UX2-P0-07 | 390px 节点表单虽为全屏 Modal，但全部高级字段连续展开；UUID 区与 Flow 同行，UUID 实际输入区域接近图标宽度 | 核心凭据难以输入，保存按钮远离当前错误 | 手机全屏 Drawer + 固定底部操作；必填/连接安全/传输/高级四段；UUID 独占一行；协议相关字段按需展示 | 390×844 首屏可完成协议、名称、地址、端口、UUID；底部操作始终可达；字段不挤压 |
| UX2-P0-08 | 手机主要操作多为 24/32px，主题开关 16px；危险按钮紧邻普通按钮 | 误触、漏触，尤其影响删除/吊销 | 手机交互热区至少 44×44px；视觉按钮可小，但用 padding 扩大 hit area；危险项进入“更多”并与普通项分组 | 320–430px 所有可交互控件命中区 ≥44px；危险操作不与高频操作并排 |

## 五、目标信息架构与用户流程

### 5.1 管理导航建议

推荐“分组但不折叠”，所有入口仍一眼可见：

```text
分发
  订阅
  分享
  平台
  规则

装配
  订阅装配
  节点

成员
  用户
  审批中心

系统
  面板配置
  日志
```

高级模式开启后，在“装配”加入 Xray 实例，在“成员”加入用户组。收起侧栏时用分隔线保留分组关系，所有图标提供 Tooltip。

此建议与 `Design2-UI.md §2.1`“平铺不分组”冲突，必须由用户确认并同步 Design 后才能构建。

### 5.2 首次发布任务清单

推荐放在订阅页首次空态顶部，不新增 `/admin` Dashboard：

```text
发布第一份订阅
1. 平台已就绪                         已完成
2. 创建订阅条目                       待完成
3. 添加至少一个节点                   待完成
4. 生成并检查配置                     未开始
5. 激活版本                           未开始
6. 以普通用户身份检查                 未开始
```

- 仅使用现有状态推导，不新增统计系统。
- 每步有一个明确动作，不把多个对象塞进单一大向导。
- 完成首次发布后折叠为“发布流程帮助”。

### 5.3 装配任务模型

顶层保持三类任务，但改为用户语言：

1. **规则素材**：维护可复用规则来源。
2. **代理策略**：组织节点和策略组。
3. **生成配置**：选择目标客户端并生成产物。

“生成配置”内的类型名称：

| 内部 key | 用户标签 | 一句话解释 |
|----------|----------|------------|
| `clash-yaml` | Clash 配置 | 生成包含节点、代理组和规则的完整 YAML |
| `sr-subs` | Shadowrocket 节点 | 生成可导入 Shadowrocket 的节点订阅 |
| `generic-subs` | 通用节点 | 生成适用于 v2rayNG / v2rayN 等客户端的节点订阅 |
| `sr-conf` | Shadowrocket 分流规则 | 生成规则配置，不包含节点订阅 |

预览必须绑定 `previewFingerprint`：目标类型、平台/规则、头部、节点、组、规则、覆盖层任一变化都会让指纹失效，页面改为“配置已变化，请重新预览”，而不是继续展示旧产物。

### 5.4 设置页六分组

| 分组 | 内容 | 保存方式 |
|------|------|----------|
| 身份与访问 | OIDC、本地认证、验证码 | 独立保存，说明影响登录入口 |
| 通知 | SMTP | 独立保存 + 测试 |
| 外观与内容 | 站点、ICON、公告、页脚 | 独立保存 |
| 运行与安全 | 模式、限流、超时、日志、调试 | 独立保存，标出需重启项 |
| 数据管理 | 导入导出、备份 | 独立任务区 |
| 危险操作 | 清空、关闭高级模式清理 | 红色独立区，默认折叠 |

页面顶部持续显示“2 个分区有未保存更改”；离开页面只在确有修改时提示。保存成功只反馈当前分组，避免用户误以为全页已保存。

### 5.5 普通用户首页任务顺序

普通用户首页应先回答“我现在该做什么”：

1. 服务/账户状态摘要。
2. 推荐或首个平台卡片。
3. 其他平台卡片。
4. Shadowrocket 分流规则。
5. 流量信息与公告。

每个平台主操作只保留“一键导入”；“复制链接”和“刷新链接”作为次要动作。刷新入口仍需明确旧链接立即失效。手机端三个动作纵向或 `主按钮 + 更多` 呈现，不能用三个 32px 小按钮挤在一行。

```css
  --ui-surface-raised: #ffffff;
  --ui-border: #cbd5e1;
  --ui-text: #0f172a;

  --ui-surface: #111827;
  --ui-surface-raised: #1e293b;
  --ui-border: #334155;
  --ui-text: #f8fafc;

```

`ConfigProvider` 的 `colorBgBase / colorBgLayout / colorBgContainer / colorBorder / colorText*` 与 Tailwind 自定义颜色都引用这些变量。这样表格、Modal、Drawer、Header 和页面容器不会再属于不同暗色体系。

## 七、统一组件与交互规范

### 7.1 PageShell

```text
PageShell
├─ Breadcrumb（层级页才显示）
├─ PageHeader（唯一 h1、描述、一个主动作）
├─ ContextBar（来源任务、未保存、后台任务、前置条件）
└─ StateContainer
   ├─ Loading
   ├─ Error + Retry
   ├─ Empty + Next action
   └─ Sections / Collection
```

- 页面头只允许一个主按钮。
- 危险操作不能进入主动作位。
- 页面描述使用用户目标，不写“四类装配器：副 Tab 选类型……”这种实现说明。

### 7.2 ResponsiveCollection

- 桌面表格行高至少 48px，操作列保留一个主动作和“更多”。
- 手机卡片只显示 3–4 个关键信息；状态放标题旁，技术标识进入详情。
- 手机卡片底部主操作占满或明确突出；次要与危险操作进入菜单。
- 空态隐藏分页、批量和清空操作。

### 7.3 FormSection

复杂表单统一三级渐进披露：

1. **必须填写：** 名称、目标、协议、服务器、端口、凭据。
2. **常用连接：** TLS、传输、SNI、ALPN、UDP。
3. **高级选项：** JSON 参数、TFO、MPTCP、网卡、路由标记、拨号代理。

折叠区标题显示“已配置 3 项”；区内有错误时自动展开。错误摘要移动焦点至第一处问题。手机使用全屏 Drawer 和固定底部“取消 / 保存”。

### 7.4 PreviewState

预览必须有四态：

- **未生成：** “完成必要选择后生成预览”。
- **生成中：** Skeleton / loading，不保留可误认的旧正文。
- **最新：** 显示生成时间和目标类型。
- **已过期：** “配置已变化，请重新预览”，旧内容可折叠查看但不可确认生成。

“确认生成”只在最新预览与当前表单 fingerprint 相等时可用。

### 7.5 浮层与反馈

- 同一时刻最多一个 Dropdown 打开；打开 Modal/Drawer 时关闭 Dropdown。
- Esc 关闭顶层浮层并回焦触发器。
- 相同 Toast 在 2 秒内合并，不堆叠。
- 短成功用 Toast；可恢复错误用页面 Alert；长任务用持续 Notification；表单错误必须落在字段附近。
- 所有默认 `Close` 改为“关闭{对象}”，并提供稳定 accessible name。

## 九、响应式与可访问性验收基线

### 9.1 断点行为

| 视口 | 导航 | 内容 | 复杂表单 |
|------|------|------|----------|
| ≥1200 | 220px 展开侧栏 | 最大宽 1440，表格优先 | 宽 Modal 或页面 |
| 768–1199 | 默认 64px 收起侧栏 | 中密度表格/双列分区 | 宽度自适应，内部不再叠第二个永久侧栏 |
| <768 | Drawer | 卡片/单列 | 全屏 Drawer + 固定底部动作 |

### 9.2 硬性基线

- 320、360、390、430、768、1024、1440 均无横向页面溢出。
- 手机所有可交互命中区至少 44×44px。
- 页面唯一 `h1`；区块从 `h2` 开始。
- 主题、账户、菜单、关闭、显示密码等纯图标控件有稳定中文名称。
- 键盘可完成登录、注册、找回、主要管理弹窗和装配步骤。
- Modal/Drawer 打开后焦点进入，关闭后回到触发器。
- 颜色对比达到 WCAG AA；状态不只靠颜色。
- 支持 `prefers-reduced-motion`；无必要自动滚动和闪烁。

## 十一、待用户确认的设计决策

以下项目存在多种合理方案或与当前 Design 冲突。报告只给推荐，不视为批准。

### D1：是否修正装配预览为强一致状态

- **方案 A（推荐）：表单变化即让预览过期，并禁止确认生成。** 最可信，改动集中在装配状态管理。
- 方案 B：每次变化自动重新请求预览。更顺滑，但频繁请求、输入抖动和错误处理复杂。
- 方案 C：保留旧预览，只显示小提示。不足以避免误判，不推荐。

### D2：是否采用自定义蓝色与完整表面 Token

- **方案 A（推荐）：主色改 `#2563EB`，采用第六章完整 Token。** 更稳重，浅暗主题统一；需修改 `Design2-UI.md §1.1`。
- 方案 B：保留 `#1677FF`，只补表面/文字/语义 Token。冲突更小，但品牌辨识度提升有限。
- 方案 C：继续只依赖 AntD 默认算法。不解决 Tailwind 与 AntD 暗色断层，不推荐。

### D3：管理导航是否从平铺改为分组

- **方案 A（推荐）：分组但不折叠。** 扫描快、不增加点击；需修改 `Design2-UI.md §2.1`。
- 方案 B：保持平铺，仅排序和分隔。改动小，任务域仍不够清楚。
- 方案 C：可折叠分组。更节省高度，但会隐藏入口，不适合当前规模。

### D4：设置页承载方式

- **方案 A（推荐）：同一路由 + 桌面分组导航 + 手机 Select。** 保留现有路由与 API，改动集中。
- 方案 B：独立子路由。深链和浏览器历史更强，但路由与未保存管理复杂。
- 方案 C：顶部 Tabs。实现简单，手机和未保存状态较弱。

### D5：手机复杂表单载体

- **方案 A（推荐）：手机全屏 Drawer，桌面宽 Modal/独立页，共用同一表单组件。** 固定底部动作且可渐进披露。
- 方案 B：全部改独立页。深链最好，但改动范围更大。
- 方案 C：保留当前全屏 Modal，仅调尺寸。不能解决分组、错误定位和底部动作问题。

### D6：首次发布任务清单位置

- **方案 A（推荐）：订阅页空态顶部，完成后折叠。** 轻量，不新增 Dashboard。
- 方案 B：新增 `/admin` 概览。扩展性强，但需要新的信息定位和指标。
- 方案 C：只改善各页空态。改动最小，跨页依赖仍不可见。

## 十二、未验证项与限制

- 高级模式业务页不属于本轮“基础模式全部界面”范围；仅验证隐藏、导航与深链守卫。
- 未连接真实 OIDC、SMTP、验证码服务，未验证邮件送达、回调成功/冲突和验证码挑战。
- 未执行文件上传、正式导入、备份下载、外部客户端 scheme 唤起、删除、Token 真正刷新和装配最终生成。
- 未使用真实读屏软件和 axe 自动扫描；可访问性结论来自 DOM、尺寸、可访问名称与浏览器交互。
- 本轮键盘焦点的自动连续 Tab 采集受浏览器控制接口限制，不能替代后续人工键盘验收。

这些限制不影响已通过浏览器直接观察到的旧预览、错误恢复、触控尺寸、响应式溢出、菜单叠加、内部枚举和暗色表面问题。

## 十三、最终建议

UIReport2 建议把改进拆成两个决策层：

1. **无需改变产品方向即可优先修正：** 旧预览、无关警告、应急/重置/OIDC 状态、跨页返回、触控尺寸、菜单互斥、可访问名称、中文空格与内部枚举。
2. **需要用户批准后进入 Design：** 主色与完整视觉 Token、管理导航分组、设置页承载方式、手机复杂表单载体、首次发布任务清单位置。

不建议先批量“美化”单页。正确顺序是：让状态可信，让手机能完成任务，让跨页流程不断裂，再统一页面骨架和配色。完成这些后，当前项目已有的路由、双态列表、ConfirmModal、Notify、主题切换和装配能力才能真正形成一个稳定、清楚、适合长期使用的小团队管理产品。
