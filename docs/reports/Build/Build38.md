## 二、分步构建与验收

### Step 1 — 表单布局与检查状态

- **前置条件** Issue21 第 8 节已确认区域位置、折叠区文案及默认折叠结果。实施前用户进一步确认使用单条状态汇总、重新检查即清空旧结果，并修复草稿变化后旧加载提示无法退出的问题。
- **目标** 新建和编辑均可在高级数据折叠时操作目标检查，检查结果按需展开，草稿改变后可立即重新检查。
- **产出** `NodesView.vue` 将检查面板作为表单直接子区域移到高级数据之前。`NodeCheckPanel.vue` 复用现有面板容器，提供带标题的区域及一个原生 `details` 汇总，显示目标总数以及通过、警告、错误、跳过的数量。展开沿用各目标卡片和脱敏产物入口。汇总具备键盘焦点样式，加载与结果状态通过 `role="status"` 播报。草稿阻断、请求错误和冲突反馈位于结果汇总外。
- **状态流转** `run()` 清除旧结果后发起检查。当前序号匹配时才接收响应或处理错误。检查请求所用草稿变化时，监听器清除结果、错误和加载状态并推进序号。结果清除会移除原生折叠容器，新结果重新以关闭状态渲染。检查 API、请求构造、保存路径和扩展数据模型沿用现有实现。
- **验收命令** 执行 `cd frontend && npm test -- tests/node-check-panel.spec.ts tests/nodes-view.spec.ts`，125 项通过。新断言覆盖新建与编辑顺序、汇总计数、默认折叠、重查清空、草稿变更后重新检查、旧响应与当前加载的隔离、草稿阻断、请求失败与 409。移动前的区域顺序断言和改动前的结果行为断言均复现旧行为。

### Step 2 — 联合门禁、隔离浏览器验收与文档

- **前置条件** Step 1 定向验收通过。
- **目标** 验证生产产物中真实检查、保存、键盘和手机交互，并更新现行设计、Issue 和归档入口。
- **复现方法** 在临时后端副本中将 `frontend/dist` 复制到 `backend/web/dist`。执行 `CGO_ENABLED=0 go build -o <隔离二进制> ./cmd/server`，以 `APP_MODE=prod`、`PORT=18107` 和独立 `DATA_DIR` 启动，从 `127.0.0.1:18107` 访问。使用 `/tmp/r35-07` 合成测试数据库的 SQLite 备份，以测试管理员登录 `/admin/nodes`。用新建 VLESS 和测试节点 `HK` 分别执行检查。
- **桌面验收** Chrome 1440×1000 下，检查按钮可直接操作。Tab 可从按钮进入汇总，Enter 和 Space 可展开与收起，展开后可按需查看脱敏产物。空地址返回三个错误，有效草稿返回三个通过，编辑 `HK` 返回一个通过、两个警告，计数与 API 一致。高级数据展开与合拢不影响结果的展开状态。通过拦截一轮真实响应，确认重查立即移除展开结果，改地址结束加载，旧响应迟到后保留最新结果。编辑态未应用 JSON 时，检查被阻断且能定位草稿。通过隔离 API 推进修订号触发真实 409，面板内提示可见，表单顶部的唯一「重新加载」可恢复检查。新建检查不生成节点，点击保存后成功创建；随后删除测试节点。检查前后 `HK` 修订号一致。
- **手机视口验收** 375×785 的浅色、深色 Drawer 均通过触控展开和收起检查结果、摘要换行与内容宽度检查，底部保存按钮在视口内。本例汇总触控高度为 64px，检查按钮至少 44px。空地址示例中，面板未检查、汇总折叠、诊断展开时分别为 138px、211px、459px。
- **验收命令** `cd frontend && npm test && npm run build` 通过，51 个测试文件、476 项。`cd backend && go build ./... && go vet ./... && go test ./... -count=1` 通过。`git diff --check` 通过。
- **文档与证据** 已同步 Design4 v1.35、Issue21 和 AGENTS，Build19 与 Design2-UI 加入指向现行设计的说明。本地脚本及截图位于 `/tmp/r35-07-impl.ue448y/`。验收范围为自动化和隔离 Chrome，实际读屏、手机真机、Docker 和远端 CI 未执行。
