## 一、目标与启动流程

镜像在实际挂载完成后准备 `DATA_DIR`，使首次空目录启动能够创建 SQLite 数据库并进入 Setup。入口采用 `su-exec` 切换身份并以 `exec` 启动服务，业务进程作为 PID 1 接收退出信号。

- 普通用户拥有的数据目录采用该目录的数值 UID/GID，保留目录属主。
- 镜像的 `app` 明确固定为 UID/GID `10001:10001`，避免 Alpine 自动分配的低位系统编号。root 拥有的数据目录将目录自身交给 `app` 用户。已有文件逐项按运行身份检查，权限冲突返回具体错误供部署者处理。
- 空的 `100:101` 目录按 v4.1.5 默认身份问题修正为 `10001:10001`。目录内容检查包括隐藏文件，检查失败直接报错。自动修正仅发生在 root 入口阶段。
- Compose `user` 或 Docker `--user` 显式指定非 root 用户时，采用指定身份进行检查和启动。
- 入口规范化 `DATA_DIR`，要求绝对路径并拒绝根目录与 `..` 路径段。以降权身份验证目录访问、临时文件创建与删除、当前模式的 SQLite 主文件及 sidecar 可读写。
- 命名卷和 bind mount 均采用同一流程。进程身份取决于实际挂载后的权限。

自动调整范围仅为数据目录自身的属主。数据库、版本文件、资源文件的内容和权限由现有存储流程管理。混合属主的历史文件可能需要部署者修正权限。只读挂载、存储端限制 chown、用户命名空间映射等环境需提供对应身份可访问的存储。

## 二、失败语义

入口发现权限失败时，输出数据目录、UID/GID 和失败原因后以非零状态退出。后端原生启动或入口检查之后的访问失败，通过 SQLite 主错误码识别权限、只读、I/O、空间不足及无法打开文件，在 Open 和迁移两条分支输出存储错误并退出。实际损坏文件继续提供应急恢复页，手动应急变量保持生效。
