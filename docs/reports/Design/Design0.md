## 一、产品定义与设计目标

### 1.1 产品定位

**自托管的 VPN 订阅管理系统**，面向 ≤10 人的小团队。管理员通过 Web UI 配置认证（OIDC 或本地账号）、管理用户、上传订阅配置文件（Clash / V2Ray / Shadowrocket 格式）和分流规则；普通用户登录后可通过「一键导入」将订阅添加到 VPN 客户端。

### 1.2 核心价值主张

- **一次获取，长期自动更新**：用户获得一次订阅链接后，即使不登录也能持续获得最新配置（通过长期下载 Token）；管理员更新订阅版本后，所有用户自动生效，无需重新分发。
- **零运维负担**：`docker compose up -d` 即可启动，所有运行时配置通过 Web UI 完成，无需 .env 文件、无需外部数据库、无需额外服务。

### 1.3 运行模式

| 维度 | 取值 | 说明 |
|------|------|------|
| 部署形态 | **单实例自托管** | 单容器 + SQLite 嵌入式存储，部署在自有服务器；外部反代做 TLS 终止，或局域网直连简化模式（见 7.1） |
| 运行模式 | **Dev / Production 双模式** | `APP_MODE` 环境变量启动时决定；**数据库按模式隔离**（独立数据库文件）；**版本文件与 `/public` 静态资源两模式共享，不按模式隔离**——Dev 上传的安装包/站点图片切回 Production 后仍可访问（Dev 定位临时调试，见 5.5） |

**模式规则**：环境变量 `APP_MODE=dev|prod`（docker compose 传入）在**启动时**决定运行模式（修改后重启容器生效），**不在运行时切换**；两种模式使用不同数据库文件（隔离范围仅数据库，文件资源边界见 1.3 表格与 5.5）。

### 1.4 核心能力（能力清单，重构必须保留）

- **认证接入**：支持 Keycloak / Auth0 / 通用标准 OIDC 与本地用户管理（邮箱+密码）两种认证体系，可混合并存；PKCE + state 持久化 + 会话凭据；「记住我」控制会话时长；**模拟 OIDC**（仅 Dev 模式）支持无提供商环境下本地调试
- **订阅内容管理**：按平台维护订阅池（每平台可创建任意多份订阅），支持文件上传与文本编辑两种方式创建版本，每份最多保留 5 个历史版本，可预览、切换、回滚
- **用户组与订阅池分发**：订阅与用户组多对多关联，每组按平台选定一份订阅，组内用户统一获得；管理员可预览池内全部订阅；未选定不兜底不回退
- **自定义订阅覆盖**：管理员可为「特定用户 + 特定平台」上传独立订阅，覆盖自动分配；支持版本管理与 Token 刷新
- **独立分享订阅**：不绑定任何用户的公开分享链接，支持版本管理、Token 刷新与吊销
- **分流规则管理**：通用规则模型（当前支持 Shadowrocket .conf），独立版本管理与下载 Token，支持一键导入
- **账号审批与启用**：自注册与 OIDC 各设独立审批开关（均默认关闭，关闭时新用户直接激活，开启后走白名单/审批流）；账号可禁用/启用
- **验证码防护**：支持 reCAPTCHA 与 Cloudflare Turnstile，管理员可勾选在注册/登录/找回密码页面启用（可全部不启用）
- **客户端安装包分发**：平台支持上传二进制/压缩包供公开下载（可被 CDN 缓存），与外部链接下载并存
- **SMTP 消息服务**：密码重置、审批结果通知、欢迎邮件（管理员勾选启用范围，默认全不启用）
- **站点自定义**：站点名称与 ICON（上传图片）自定义，ICON 走可缓存路径
- **长期下载 Token 体系**：用户 Token、分享 Token、规则 Token 三类独立体系，支持手动轮替、吊销、级联清理
- **访问日志**：记录全部下载请求（类型、用户、平台、IP、状态、失败原因），按日期查询，默认保留 90 天自动清理
- **分级运行日志**：debug / info / warn / error 四级，管理员可在面板配置中**运行时切换**（立即生效并持久化）
- **实时日志流**：SSE 实时推送运行日志（HTTP 请求/响应、调试输出，与 docker compose logs 同源），便于调试与对接 WAF
- **数据清理**：清空访问日志；一键清空所有数据（完全重置回 Setup，需确认词 + 二次确认）
- **密码救援**：忘记密码未配置 SMTP 时管理员可在用户管理直接重置用户密码（随机 8 位易读密码）；**管理员自身密码仅能通过应急恢复模式重置**——设置 `RESET_ADMIN_PASSWORD` 环境变量重启进入应急页（其他管理员的密码可在用户管理直接重置，见 3.4.5）；数据库损坏/关键配置损坏自动触发的应急页仅提供重新初始化（见 3.8）
- **速率限制**：登录、注册、找回密码、下载 API 独立限流（默认登录 10/分钟、注册与找回 5/分钟、下载 20/分钟），超限返回 429 + Retry-After
- **全栈 Web UI**：Ant Design Vue + Tailwind 重构；首页订阅卡片、管理面板（订阅/用户组/分享/平台/用户/审批中心/规则/面板配置/日志）、个人中心、暗色模式、多端（手机/平板/台式机）友好

### 1.5 设计原则（重构时的决策准则）

| 原则 | 说明 |
|------|------|
| 简单轻量 | 不做不必要的抽象；后端单二进制 + 嵌入式存储，前端按需打包，项目自身资源零 CDN 运行时依赖（外部服务如验证码脚本除外） |
| 零配置启动 | 首次启动即进入 Setup 引导；除端口等运维参数外一切配置走 Web UI |
| 双模式运行 | Dev / Production 模式由启动参数（`APP_MODE`）决定，使用独立数据库；Dev 模式提供模拟 OIDC |
| 路径分级 | `/public` 静态资源（站点图片、安装包）可被 CDN 缓存；订阅/规则下载始终禁止缓存 |
| 性能优先、简约优先 | 多端（手机/平板/台式机）友好的响应式设计；组件库按需引入 |
| 安全底线不妥协 | 路径穿越防护、密钥加密存储、Token 脱敏日志、实时权限校验、订阅下载防缓存 |
| 数据一致性 | 版本创建/切换的并发安全（事务 + 写锁）、级联删除保证无孤儿数据 |
| 不过度防御 | 合理假设输入有效，不堆叠冗余的 nil/空值检查链与 fallback；网络安全边界由部署者控制 |

## 二、用户角色与权限模型

### 2.1 角色体系

系统只有两种角色，权限来源于持久化用户表（非会话 claims），**每次请求实时查库**，不做任何缓存：

| 角色 | 来源 | 能力边界 |
|------|------|---------|
| **管理员（admin）** | 首个完成认证流程的用户自动成为管理员（受「首管理员初始化标记」保护，见 2.5；Setup 只写配置、不创建任何用户） | 全部管理面板：用户/订阅/用户组/分享/平台/规则/审批中心/面板配置/日志；首页可预览订阅池内全部订阅 |
| **普通用户（user）** | 管理员诞生后新登录的用户默认为普通用户；管理员手动创建的本地用户；审批通过的自注册用户；OIDC 白名单命中或审批通过的用户 | 仅首页（订阅卡片）+ 规则浏览页 + 个人中心；无管理入口 |

### 2.2 用户组与订阅池机制（取代原 default/advanced 二级分级）

**订阅池（按平台独立）**：

- 每个平台可创建**任意多份**订阅（订阅池），每份订阅保留 5 个历史版本（版本管理规则见 4.1）
- 订阅与用户组**多对多关联**：创建/编辑订阅时可多选关联组；一份订阅可被多个组共享
- 订阅创建需指定平台、名称与标识（标识为小写字母数字连字符，**全局唯一**——与分享订阅、规则、自定义订阅**共用同一标识命名空间**，创建时跨四类资源交叉校验冲突）；**分享订阅与自定义订阅的标识由系统自动生成（名称 slug + 随机短码；slug 仅取名称中 ASCII 字母数字连字符片段，中文等字符丢弃，slug 为空时仅用随机短码），自动生成值与手填标识同样参与唯一性校验，冲突时自动重试（**随机短码为 6 位小写字母数字，最多重试 3 次，仍冲突则报错并记录日志**）；手填标识长度 3~64 字符；同一平台允许多份订阅并存

**用户组**：

- 组属性：名称（**全局唯一**校验）+ 关联订阅集合 + **每平台选定一份订阅**（从关联订阅中任选，可不选）——组级统一选定，组内所有用户统一获得
- **预置默认组**：系统初始化自动创建（与 3 个默认平台同批）；不可删除、可改名（受唯一校验）、可不关联订阅
- 新建组/改名/删除见 3.4.2；删除组时组内用户自动迁入默认组（见 4.4）

**用户归属**：

- **单组互斥**：一个用户仅属一个组；新用户（OIDC / 自注册 / 管理员创建）自动加入**默认组**；管理员归属默认组（可改，但首页预览不受组限制）
- 管理员可在用户管理随时调整用户所属组；**换组无需清理下载 Token**（实时解析自动跟随新组，见 4.2）

**分发规则**：

- 用户首页按「所属组在该平台的选定订阅」展示订阅卡片；组未选定该平台订阅 → 卡片显示「未分配，请联系管理员」，**不生成 Token，不兜底不回退**（延续原「不降级不升级」原则）
- 自定义订阅（用户+平台）优先级高于组分配（见 2.3）
- 管理员首页预览订阅池内**全部订阅**（按平台分组、非当前平台默认折叠，每份三按钮），不受组限制（见 3.3）
- **平台标识为独立命名空间**（不参与订阅/分享/规则/自定义四类标识校验，见 3.4.4）

### 2.3 自定义订阅（管理员强制覆盖）

管理员可为特定用户在特定平台上上传一份**完全独立**的订阅配置文件，覆盖该用户在该平台的组分配。用于例外场景（如某个用户需要与同组其他用户不同的节点配置）。

**覆盖规则**：

- 上传时必须指定适用平台；每用户每平台最多一份，同一平台再次上传即覆盖（**复用原记录与标识，仅创建新版本**——Token 复用键 user+platform+custom_sub_id 保持稳定，见 4.2）
- 自定义订阅同样支持版本管理（上传/切换/预览/删除，最多 5 个版本）
- 自定义订阅使用**独立标识的用户下载 Token**（Token 关联 custom_sub_id，见 4.2 三态模型），优先级高于组分配；**上传/覆盖自定义订阅时删除该用户在该平台原有的无标识（组解析）Token**（旧链接立即失效，防止旧链接继续返回组内容造成「覆盖失效」观感）；支持手动刷新 Token
- 删除自定义订阅 → 级联清除 custom_sub_id 指向的 Token，用户下次访问首页重新生成无标识（组解析）Token
- **用户首页显示**：有自定义订阅的平台卡片显示「已被分配自定义订阅」提示 + 自定义订阅操作按钮（替换组分配按钮）
- **管理员首页显示**：管理员预览池内全部订阅；自定义订阅独立展示于对应用户管理（机制不变）

### 2.4 独立分享订阅

不关联任何用户的独立分享订阅链接。任何人持有该链接即可下载订阅配置，无需登录。

**设计规则**：

- 与自定义订阅是**两个独立功能**：自定义订阅绑定用户+平台并替换自动分配；分享订阅不绑定用户、不区分平台、不区分用户组——管理员上传什么内容，下载者就获得什么
- 每个独立分享订阅自动生成独立下载 Token；创建/刷新后链接即刻可用，吊销后链接立即失效但文件与版本历史保留
- 支持完整版本管理（同订阅逻辑）
- 使用场景：给外部人员临时访问、创建团队公共链接方便分发

### 2.5 管理员保护规则（四重防护）

防止误操作锁死系统：

1. 禁止管理员删除自己
2. 禁止删除最后一个管理员（系统内管理员数量必须 ≥ 1）
3. 禁止管理员修改自己的角色（role）
4. 禁止禁用最后一个活跃（未禁用）管理员（禁用场景延伸保护，见 4.6）

**角色变更**：admin↔user 角色变更仅可由**其他管理员**执行（管理员自身受第 3 条保护）；admin→user 降级时**级联清除其全部显式订阅 Token**，且显式 Token 下载端点实时校验持有人当前仍为管理员（见 4.2）

**首管理员初始化标记（改进后）**：Setup 完成时只标记系统已配置，**不创建任何用户账户**；**首个完成认证流程的用户**（OIDC 首次登录 / 首个自注册用户）触发管理员诞生，并写入「已初始化」标记。**当用户表为空（0 行）时忽略该标记**——数据库重置、迁移或全部用户被删除后，系统可自动重新开始（适用于所有认证模式）；已有用户时该标记防止意外产生第二个管理员。**空表判定口径**：任何用户记录（含待审批）存在即算非空——待审批记录占表时不触发首管理员逻辑。**原子性**：「检查空表 → 写入管理员 + 置位标记」在单个事务内完成（并发串行化），并发首登录/首注册只产生一个管理员。

### 2.6 账号状态、来源与启用规则

**账号状态**：`待审批` / `已激活` / `已禁用`。仅「已激活」账号可登录；「已禁用」账号的会话与下载 Token 一并失效。

**来源标注**：OIDC / 本地创建 / 自注册，用于 UI 展示与区分。

**启用规则**（见第四章 4.6；两个独立审批开关，均默认关闭）：

- 自注册用户：受「自注册审批开关」控制——关闭（默认）：注册后**直接激活**；开启：注册后进入待审批，由管理员在审批中心激活或拒绝
- 自注册入口：自注册开关默认关闭；**注册入口在用户表为空且「允许本地登录」开启时始终显示**（见 3.2）；**用户表为空时首个注册者免审批直接成为管理员，不受审批开关影响**
- OIDC 用户：受 OIDC 审批功能开关控制——关闭（默认）：新 OIDC 用户直接激活，白名单不生效；开启：Role/Group 白名单（值列表 + 可配置声明路径，见 3.4.8）命中 → 自动激活，未命中 → 进入待审批；**白名单未配置或为空时跳过校验直接激活**（**已确认取舍：白名单为空时新用户直接激活；保存配置时面板显著警告「白名单为空，新用户将全部直接激活」，防静默降级**，见 3.4.8）
- 管理员创建的本地用户：默认直接激活
- 用户表为空时，首个登录/注册者始终直接激活并成为管理员（不受开关影响，防死锁）
- **首管理员检查顺序**：「用户表是否为空 → 空则直接成为管理员」的检查**先于**自注册/OIDC 审批开关判定——即首个注册者/登录者永远免审批直接成为管理员，不受任何审批开关影响（防「审批开启后首注册者进待审批、永无管理员可审批」死锁）

### 2.7 用户字段语义

| 字段 | 语义 |
|------|------|
| `user_id` | 主键，系统生成，**内部稳定**（不随 OIDC 绑定/合并变化）；OIDC 身份通过 `oidc_subject` 列关联 |
| `oidc_subject` | OIDC 提供商返回的 subject 标识，**唯一（可空）**；OIDC 登录按此匹配；自动合并/手动绑定即写入此列（见 4.6） |
| `username` / `email` | 由认证结果或注册/创建信息提取；邮箱**全局唯一**（NULL 除外，见下）；username **无唯一约束**，仅展示用 |
| `credential_version` | 凭据版本号（会话立即失效机制，见 5.4）；修改邮箱/密码重置/禁用时递增（删除=删行、一键清空=密钥轮换，不走版本号，见 #140） |
| `role` | `admin` / `user` |
| `group_id` | 所属用户组（单组互斥，见 2.2）；新用户自动加入预置默认组 |
| `password_hash` | 本地密码哈希（bcrypt）；为空 = 不可本地登录（OIDC-only 用户） |
| `user_source` | 来源标注：OIDC / 本地创建 / 自注册，用于 UI 展示 |
| `status` | 账号状态：待审批 / 已激活 / 已禁用；仅已激活可登录（审批拒绝即删除账号，无独立「已拒绝」状态） |

**邮箱可空边界**：OIDC 提供商未返回 email 时允许创建用户（email 为空，唯一约束对 NULL 不生效，多个无邮箱用户可并存）；无邮箱用户 UI 标注「无邮箱」，无本地登录/密码重置/自动合并能力；管理员可在用户管理手动补填邮箱后获得相应能力（见 4.6）

## 三、功能全景（重构目标功能清单）

### 3.1 首次部署与 Setup 引导

管理员执行 `docker compose up -d` 启动服务后（环境变量 `APP_MODE=dev|prod` 启动时决定运行模式，默认 prod，见 1.3）：

1. 访问网站任意路径 → 后端检测到系统未配置 → 前端路由守卫自动跳转到 Setup 首次配置页（页面展示当前模式：Dev / Production）
2. **选择认证方式（面向 0 基础用户的引导结构）**：Setup 仅写入系统配置，**不创建任何用户账户**；管理员由首个完成认证的用户产生（见 2.5）
   - **快速开始（推荐）**：本地账号模式——完成基础配置即可使用，无需任何外部依赖
   - **高级配置**：接入单点登录——Keycloak / Auth0 / 通用标准 OIDC / 模拟 OIDC（仅 Dev 模式可见可选）
3. （高级配置）填写提供商参数（Base URL、Realm/域名、Client ID、Client Secret）与回调地址、前端地址（模拟模式自动填充）
4. 点击「测试连接」验证 OIDC 配置正确性（不落库，仅验证；模拟模式始终通过）——**测试机制：① 验证提供商发现文档可达性与配置完整性（Base URL/Realm/Client ID/回调地址）；② 客户端凭据校验——调用提供商 token 端点以 client_credentials 换取 token，验证 Client ID/Secret 正确性（不依赖用户交互）；提供商不支持该授权类型时降级为警告而非失败，不阻断保存**
5. 点击「完成配置」→ 系统自动生成签名密钥（同时作为加密密钥派生源）→ 写入配置存储 → 标记系统已配置
6. 跳转登录页 → 按所选模式登录 → 首个完成认证流程的用户自动成为管理员（**用户表为空且本地登录开启时登录页始终显示注册入口**，首个注册者免审批直接成为管理员；本地登录关闭但已配置 OIDC 时，首个 OIDC 登录者成为管理员；见 3.2）

**设计要点**：

- 切换提供商类型时**保留已填字段**（各提供商参数独立存储，互不覆盖）；**切换前 UI 显著提示：「已绑定当前提供商 OIDC 身份的账号，在新提供商下 OIDC 登录将失效（subject 不匹配），需在新提供商重新绑定或新建账号；本地密码登录不受影响」，并引导「切换到新提供商前请先为相关管理员设置本地密码」**；旧绑定不自动迁移
- 回调地址与前端地址在 Setup 页预填当前浏览器域名，减少手动输入
- **Setup 完成页显著步骤式提示「请部署者本人立即注册/登录成为管理员」**（先到先得机制：首个完成认证的用户成为管理员，避免团队中他人抢先）；部署向导同步强调（见 7.1）
- Setup 完成后可随时在管理面板修改 OIDC 参数（含切换提供商类型、重新测试连接），无需重启服务
- **认证模式关系**：**本地登录为基底（默认开启）**，OIDC 为可选叠加——Setup 后仍可在面板配置接入 OIDC；「认证模式只读」仅指 OIDC 提供商类型在三种提供商之间切换，本地与 OIDC 不互斥（见 3.4.8）
- **运行模式（Dev/Prod）由启动环境变量决定**，修改需重启容器生效（不在运行时切换，见 1.3）
- **外部依赖提示**：验证码（reCAPTCHA/Turnstile）与 OIDC 回调均依赖公网可达——验证码仅适用于可访问外网的部署，局域网直连模式不建议启用（见 3.2）；OIDC 回调要求公网可达的 HTTPS 域名，局域网直连模式（内网/无域名）可能无法完成回调，接入前请确认部署形态（见 7.1）

### 3.2 认证与登录

**OIDC 登录**（标准 Authorization Code + PKCE）：

1. 用户点击登录 → 后端生成随机 state 与 code_verifier → 持久化（带 10 分钟 TTL）→ 下发 state 到浏览器 Cookie（HttpOnly）→ 302 重定向到提供商授权页
2. 提供商认证成功后回调 → 后端三重校验（Cookie state == 回调参数 state == 存储记录）→ 用 code_verifier 换取 token → 解析身份信息 → 查/建用户 → 签发会话凭据；**未命中白名单进入待审批时不签发会话，直接 302 到前端 `/pending` 页展示「账号待审批」提示（无凭据参数，不经凭据中转页）**（见 4.6）
3. 302 重定向到前端中转页（携带会话凭据）→ 前端提取并存到本地存储 → 清空 URL → 进入首页

**待审批用户重复行为**：已处于待审批的用户再次 OIDC 登录/重复注册时，提示「已提交，等待审批」，**不重复创建记录**（见 4.6）

**模拟 OIDC 登录**（仅 Dev 模式，模拟模式被选为认证方式时）：

- 登录页展示**模拟登录表单**：输入邮箱即可登录（**邮箱同时作为用户名与 subject**，用户名可留空，留空时取邮箱 @ 前缀），无需真实提供商
- 可**附加模拟 role/group 属性**（勾选role/group后输入对应值），用于测试 Role/Group 白名单与审批逻辑（见 4.6）
- **email_verified 可勾选**（默认勾选=已验证），用于测试自动合并绑定分支（已验证/未验证）
- **邮箱冲突行为**：模拟 OIDC 用户与本地用户共用同一 Dev 数据库（邮箱唯一约束在库内生效）——模拟登录输入邮箱与既有本地账号冲突时，**按 4.6 自动合并/冲突分支正常处理**（email_verified 勾选 → 自动合并绑定；未勾选 → 提示冲突），与真实 OIDC 行为一致，不引入 Dev 专属特殊逻辑；测试者需知悉自动合并会改写既有账号状态；**模拟 OIDC 的 subject 固定为输入的邮箱**（同一邮箱重复模拟登录命中同一用户，自动合并/冲突测试可复现）
- 模拟用户同样遵循账号状态与启用规则

**本地登录**（邮箱 + 密码；「允许本地登录」**默认开启**——本地登录为基底，OIDC 为可选叠加）：

- 邮箱为唯一标识；密码为 bcrypt 哈希校验
- 失败提示统一措辞（不区分「邮箱不存在」与「密码错误」，防枚举）；待审批/已禁用账号返回通用提示「账号未激活或已被禁用」
- 受速率限制；仅「已激活」状态账号可登录

**自注册**（仅当「允许自注册」开启，依赖本地登录开启；**默认关闭**，管理员显式开启后才出现注册入口；**例外：用户表为空且「允许本地登录」开启时注册入口始终显示**——本地登录关闭时注册入口隐藏（注册产物无法本地登录，无意义），见 2.6）：

- 登录页提供注册入口 → 填写用户名 + 邮箱 + 密码（+ 确认密码）→ 提交校验（邮箱唯一）
- 注册后按「自注册审批开关」处理——关闭（默认）：直接激活可登录；开启：进入**待审批**状态，需管理员在**审批中心**激活后方可登录；**注册提交后显示明确提示页「注册成功，等待管理员审批」**（见 4.6）
- 用户表为空时，首个注册用户自动成为管理员（免审批）

**验证码防护**（reCAPTCHA / Cloudflare Turnstile）：

- 管理员在面板配置中**手动勾选**启用页面：注册 / 登录 / 找回密码（可全部不启用，默认不启用）
- 配置验证码提供商与站点/服务端密钥；**未配置密钥时跳过校验**（便于本地开发）
- 前端渲染验证码组件，后端调用提供商验证接口校验 token
- **适用边界**：验证码脚本与校验均依赖外部网络，仅适用于可访问外网的部署，局域网直连/无外网部署不建议启用；**前端验证码脚本加载失败时显示明确错误提示**（如「验证码服务不可用，请联系管理员」），不静默卡死

**忘记密码**（本地账号）：

- 输入邮箱 → 已配置 SMTP 时生成一次性重置令牌（1 小时有效）并发送邮件；未配置时提示联系管理员（管理员可在用户管理直接重置该用户密码，见 3.4.5）
- 无论邮箱是否存在，均提示「若该邮箱已注册，重置链接已发送」（防枚举）
- 用户点击邮件链接 → 校验令牌 → 设置新密码 → 完成

**会话凭据**：

- 登录时可选「记住我」：勾选 → 会话 7 天；不勾选 → 24 小时
- 仅存用户标识 + 凭据版本号 + 标准声明，角色/组归属等权限信息**不放入凭据**，每次请求实时查库（凭据版本号见 5.4）

**登录页布局**（区块化）：

- OIDC 登录区块：仅当 OIDC 已配置时显示（含模拟 OIDC 时显示模拟登录表单）
- 本地登录区块：仅当「允许本地登录」开启时显示（含记住我、忘记密码入口）
- 注册入口：仅当「允许自注册」开启时显示（**用户表为空且「允许本地登录」开启时始终显示**，见 2.6）
- **待审批提示页（`/pending`）**：无凭据独立页面，展示「账号待审批，等待管理员激活」说明（OIDC 未命中白名单/注册后进入待审批时跳转至此，见 3.2）
- 暗色模式切换入口常驻；按管理员勾选在对应区块展示验证码组件

**设计要点**：

- state 记录用后立即删除（防重放）；过期记录定时清理
- OIDC 与本地登录共用同一套会话签发/验证机制（凭据格式统一）
- 同浏览器已登录用户访问登录页自动跳过

### 3.3 用户首页（Home）

**顶部栏**：左侧站点名称（面板配置的站点名称，未设置时显示默认标题）+ 订阅更新时间戳（普通用户=其可见订阅——组选定与自定义——最新更新时间的**最大值**；管理员=订阅池内全部订阅的最新更新时间）；右侧：管理面板入口（仅管理员）、用户名 + 角色标签（普通/管理员）+ 所属组名、退出、暗色模式切换。

**主体 — 平台卡片网格**（响应式：大屏 3 列 / 中屏 2 列 / 小屏 1 列）：

- 平台名称、平台描述
- 订阅区段（显示规则见 2.2/2.3：普通用户按所属组选定展示一份、未选定显示「未分配，请联系管理员」；管理员预览池内全部订阅）；角色标签旁显示所属组名
- 三个操作按钮：**一键导入**（按客户端 scheme 拼接 URL 并跳转唤起客户端，**多个 scheme 时取第一个**）、**复制链接**（弹窗展示完整订阅 URL，点击即复制；**多 scheme 时对话框内可切换**）、**刷新链接**（刷新下载 Token，旧链接立即失效）
- **下载客户端按钮（双模式）**：平台上传了本地安装包 → 显示「本地下载」（公开路径，可 CDN 缓存）；配置了外部下载链接 → 显示「链接下载」；两者都有则显示两个按钮（见 4.7）

**其他区域**：公告栏卡片（管理员在面板配置中维护，有内容才显示，**仅登录后首页展示**——登录页/Setup 不展示）、分流规则入口卡片（跳转规则浏览页）。

### 3.4 管理面板（侧边栏导航）

管理面板为独立布局：左侧固定宽度侧边栏（当前路由高亮），右侧内容区。移动端侧边栏默认收起，通过汉堡按钮展开。包含 9 个模块：

#### 3.4.1 订阅管理

- 列表页按平台分组展示订阅池；每份订阅展示：名称、当前版本号、关联组、**「被哪些组选定中」标记**（便于删除/改关联前评估影响）
- 创建订阅：指定平台 + 名称 + 标识（小写字母数字连字符，**全局唯一**——与分享订阅、规则、自定义订阅共用同一标识命名空间，创建时跨四类资源校验冲突）+ 关联用户组多选（可为空）；同一平台允许多份订阅并存；**创建成功后弹窗引导「关联用户组 → 每平台选定」两步（直达组管理，含「跳过」），与新建平台引导、默认组引导构成完整新手链路**
- 版本管理页：版本列表（版本号、创建/更新时间、当前激活标识）、**两种方式创建新版本**（文件上传 / 在线文本编辑）、切换当前版本、预览内容、删除旧版本
- **编辑订阅**：可修改名称与关联用户组（取消关联仍受「该组正在选定此订阅则拒绝」约束，见 3.4.2）；**平台创建后不可修改**
- 版本管理统一规则（见 4.1）：每份订阅最多 5 个版本、不可删最后一个、**不可删除当前激活版本（须先切换）**、上传/编辑后自动切换为当前

#### 3.4.2 用户组管理（独立模块）

- **分发引导**：首管理员完成首次登录后，管理面板显示一次性引导提示「为默认组配置订阅」（直达组管理）；删除订阅/平台影响组选定后，本模块**高亮受影响组并提供「重新选定」快捷入口**（见 4.4）
- 组列表：组名、关联订阅数、组内用户数；预置默认组带标识且不可删除
- 组 CRUD：新建/改名（名称全局唯一校验）/删除（二次确认；删除后组内用户自动迁入默认组，见 4.4；默认组不可删）；**组标识由系统自动生成**（内部引用用，无需用户输入，见 5.3）
- **每平台选定订阅**：每个组按平台从关联订阅中选定一份（可不选）；组级统一选定，组内用户统一获得（见 2.2）；**选定变更时 UI 提示影响用户数**（防误操作导致未分组用户全员「未分配」）
- **关联订阅管理**：为组多选关联订阅；取消订阅与组的关联时若该组正在选定此订阅 → 拒绝操作，提示先去改选（见 4.4）

#### 3.4.3 分享订阅管理（独立模块）

- 独立列表页：名称、创建时间、当前版本号、Token 状态（有效/已吊销）
- 创建对话框：填写名称（**不强制唯一**；**标识由系统自动生成**——名称 slug + 随机短码，与订阅/规则/自定义订阅共用全局唯一命名空间，冲突自动重试，见 2.2）→ 上传第一个版本（文件或文本）→ 自动生成分享 Token
- 操作：**改名**（分享订阅创建后仅可改名）、版本管理（独立子页面）、复制分享链接（仅 Token 有效时）、刷新 Token（旧链接立即失效）、吊销 Token（**物理删除 Token 记录**，链接立即不可用，文件与版本保留；分享订阅表以 token_status 标记展示「已吊销」状态，刷新时清除标记并新建 Token）、删除（级联删除文件 + Token）

#### 3.4.4 平台管理

- 平台 CRUD（**创建后标识不可修改**，名称/描述/scheme 可编辑；**标识由系统自动生成**——名称 slug + 随机短码，内部引用用）；系统初始化自动创建 3 个默认平台（Clash Verge / v2rayNG / Shadowrocket），内置各自的客户端导入 scheme；**平台标识为独立命名空间**（不参与订阅/分享/规则/自定义四类标识校验，见 2.2）；**新建平台后 UI 引导管理员为各用户组选定该平台的订阅**（防创建后全员「未分配」）
- 每个平台可配置：名称、描述、多个客户端 scheme（一键导入取第一个）、**附加响应头**（键值对列表，该平台订阅下载时额外返回；值支持 `{frontend_url}` 占位符；默认平台 clash-verge 已预置三条兼容头，见 4.3）、**客户端安装包**（两种来源并存）：
  - **本地上传**：上传二进制/压缩包文件（≤300MB），存至可缓存路径，公开下载；**可单独删除本地上传的安装包**（二次确认，级联删文件，恢复为仅外部链接/无下载来源状态）（见 4.7）
  - **外部链接**：填写下载地址（原有 download_url 能力）
- 删除平台为危险操作：级联删除该平台全部订阅（含版本文件）、用户 Token、自定义订阅（含版本文件）、**所有组在该平台的关联与选定**、本地上传的安装包文件，需二次确认

#### 3.4.5 用户管理

- 用户列表：用户名、邮箱、角色标签、**所属组标签**、**来源标注**（OIDC / 本地创建 / 自注册）、账号状态（待审批/已激活/已禁用）、自定义订阅平台标记、操作按钮
- 用户来源：OIDC 登录自动创建；管理员**手动创建本地用户**（用户名 + 邮箱 + 密码，邮箱唯一冲突提示）；自注册用户（激活受自注册审批开关控制）
- 操作：**编辑**（**分组选择**——下拉切换所属用户组，换组无需清 Token，下载实时解析自动跟随新组；管理员本人可改组但不影响预览）、**角色变更**（admin↔user，仅可由其他管理员操作；admin→user 降级时级联清除其全部显式订阅 Token，见 2.5/4.2）、**上传自定义订阅**（选择适用平台 → 上传**文件或文本**；**标识由系统自动生成**，见 2.2）、**删除自定义订阅**（恢复组分配）、**吊销所有下载 Token**、**设置/重置密码**（**可对任意用户执行（含其他管理员）；管理员自身密码仅能通过应急模式重置**，见 1.4/3.8；已配置 SMTP 时可选触发重置邮件——**触发重置邮件 = 发送一次性重置链接（1 小时 TTL，用户自设密码）**；**直接重置** = 二次确认后系统随机生成 8 位密码——大小写字母 + 数字，去除易混淆字符 i I o O 0 l L，无特殊符号——对话框内展示供管理员复制，即时生效，**重置后该用户全部现有会话立即失效**；**两种方式二选一**；是忘记密码流程未配置 SMTP 时「联系管理员」的兜底手段；**无邮箱用户可在此手动补填邮箱**，补填后获得设置密码/密码重置能力，见 4.6）、**清除 OIDC 绑定**（清空该用户 oidc_subject，释放绑定占用——用于切换提供商后旧绑定失效或绑定错误的场景，清除后用户可在个人中心重新绑定，见 4.6）、**禁用/启用账号**（管理员可禁用自己，但会话立即失效即登出；仍受「禁止禁用最后一个活跃管理员」保护）、**删除用户**（管理员保护规则见 2.5）
- 待审批用户的激活/拒绝集中在**审批中心**处理（见 3.4.6）
- groups 字段已转正为组归属（见 2.7）；用户分组在编辑弹窗中调整

#### 3.4.6 审批中心（独立模块）

- 独立列表页：待审批用户（自注册用户 + 未命中 OIDC Role/Group 白名单的 OIDC 用户），展示来源、用户名、邮箱、申请时间、OIDC 附加角色/组信息（如有）；**OIDC 用户的 role/group claims 以快照存入用户表可空 JSON 列**（仅审批展示用，拒绝即随账号删除，见 4.6）
- 操作：**通过**（激活账号）、**拒绝**（删除账号，邮箱释放可重新注册）、批量通过；被拒用户无记录保留（与「拒绝即删除」一致），通过的用户在用户管理中可见
- 审批结果（通过/拒绝）均按配置发送通知邮件——**拒绝通知在点击「拒绝」动作时触发发送**（可勾选，见 3.4.8 SMTP 范围）；**欢迎邮件在所有新用户首次激活时发送**（审批通过、直接激活、白名单命中、管理员创建均发送；自注册提交时仅创建待审批账号不发，见 4.6）

#### 3.4.7 规则管理

- 规则列表：名称、客户端类型（当前仅 Shadowrocket）、当前版本号、**Token 生成/上次刷新时间**；规则创建后仅可改名（客户端类型与 scheme 创建后不可修改）
- 创建规则：名称 + 客户端类型 + 客户端 scheme（用于一键导入）→ 上传首个版本（**文件或文本**）→ 自动生成规则 Token；**标识与订阅/分享订阅/自定义订阅共用全局唯一命名空间**（见 2.2）
- **规则 Token 公开边界**：规则 Token 为**全局共享**（每规则一份，不绑定用户）——**任何持有链接者均可下载，不随用户禁用/删除失效**；3.5 用户规则页 UI 提示「规则内容公开，链接请谨慎分发」（见 4.2）
- 操作：版本管理（同订阅模式）、复制下载链接、刷新 Token（旧链接立即失效）、删除（级联删除文件 + Token）

#### 3.4.8 面板配置

- **OIDC 配置**：查看/修改提供商参数（Client Secret 回显脱敏）、测试连接、切换提供商类型（保留已填字段；**切换前提示已绑定旧提供商 OIDC 身份的用户在新提供商下登录将失效，建议先为相关管理员设置本地密码，见 3.1**）；**接入提示：OIDC 回调要求公网可达的 HTTPS 域名，局域网直连模式（内网/无域名）可能无法完成回调**（见 3.1）
- **OIDC 启用规则**：OIDC 审批功能开关（默认关闭；关闭时新 OIDC 用户直接激活）；开启后维护 **Role/Group 白名单**（值列表 + **可配置声明路径**，如 `realm_access.roles` / `groups` / `roles`，默认常见值下拉可选，兼容各类提供商），命中自动激活，未命中进入审批中心；**白名单未配置或为空时跳过校验直接激活**（已确认取舍，见 2.6）；**保存时若审批开关开启且白名单为空，显著警告「白名单为空，新用户将全部直接激活」**（防静默降级）
- **本地认证配置**：允许本地登录开关（**默认开启**——本地登录为基底，OIDC 为可选叠加）、允许自注册开关（依赖本地登录开启；**自注册默认关闭**）、自注册审批开关（独立于 OIDC 审批开关，**默认关闭：自注册用户直接激活**；开启后注册者进入审批队列；用户表为空的首个注册者始终免审批）；**保存时若本地登录与 OIDC 均不可用（本地登录关闭且 OIDC 未配置/已清空），禁止保存并显示显著警告**（强制至少一种认证方式可用，防止系统进入无法登录的死锁状态）
- **验证码配置**：选择提供商（reCAPTCHA / Turnstile / 关闭）+ 站点密钥 + 服务端密钥；勾选启用页面（注册/登录/找回密码，可全不选）；**勾选启用与保存时均校验对应密钥已配置（防静默降级）**，并提示验证码依赖外部网络、局域网直连部署不建议启用（见 3.2）
- **SMTP 配置**：服务器/端口/账号/密码（加密存储）/发件人/是否启用 TLS；**勾选启用范围**（密码重置邮件 / 审批结果通知 / 欢迎邮件，默认全不启用）；**「发送测试邮件」按钮**（发送到当前操作管理员的邮箱，验证 SMTP 服务器/端口/账号/密码正确性，失败返回具体错误信息）
- **站点信息**：站点名称（**≤50 字符**，浏览器标题/登录页/首页展示）、站点 ICON（上传图片文件，**≤2MB、常见图片格式白名单**，走可缓存路径；**可删除恢复默认**）
- **运行模式信息**：展示当前模式（Dev / Production，由启动环境变量决定，修改需重启容器）
- **速率限制配置**：登录（默认 10/min）、注册（默认 5/min）、找回密码（默认 5/min）、下载（默认 20/min）；均按 **IP 维度**计数，NAT/反代共享 IP 场景由部署者调高阈值；**修改后立即生效**（每次请求读取当前配置）；**面板展示当前 IP 解析策略（TRUST_PROXY 生效值）**，便于排查共享 IP 限流误伤；**auto 模式下提示伪造风险：局域网直连的客户端可构造转发头伪造 IP 绕过限流，建议直连部署设 `TRUST_PROXY=off`**（见 6.4）
- **日志级别**：debug / info / warn / error **运行时切换**（环境变量 `LOG_LEVEL` 为初始值；面板修改立即生效并持久化，运行日志与实时日志流同步生效）
- **系统公告栏**：编辑公告内容（**纯文本 ≤2000 字符，前端转义渲染禁 HTML**，防存储型 XSS；首页展示）
- **调试模式开关**：开启后 5xx 错误响应返回详细内部信息（生产默认关闭，状态持久化，重启保留）
- **危险操作区**：一键清空所有数据（**固定确认词 `RESET`** + 二次确认 → 完全重置回 Setup，见 4.8；**与应急页操作码机制相互独立**，见 3.8）

### 3.8 应急恢复模式（管理员密码救援）

面向管理员忘记/丢失密码或数据库损坏的最后救援手段，系统进入**应急模式**（阻塞式特殊界面，暂停对外提供正常服务）。

**触发条件（能力分级，见「设计要点」）**：

- **手动触发**：启动时检测到环境变量 `RESET_ADMIN_PASSWORD` 已设置（值非空）→ 进入应急模式（管理员密码遗忘/丢失等场景均通过此变量触发）
- **自动触发**（仅以下两类，页面不含重置密码能力）：
  - 数据库无法连接/损坏（含完整性检查不通过）
  - 关键配置损坏（如 configured=true 但签名密钥缺失）
- 其他密码类异常不做自动检测（bcrypt 哈希无法静态判定密码有效性）；**认证死锁**（如本地登录被关闭且 OIDC 不可用，见 3.4.8 警告）等场景由部署者设置该环境变量重启进入应急页救援

**一次性操作码防护（单一校验机制）**：应急模式触发时，运行日志（docker compose logs 可见）输出**一次性操作码**（**8 位大写字母+数字，去除易混淆字符**）；应急页操作（重置密码/重新初始化）前须输入该码——**操作码兼承担确认词职能，页面不展示任何词**；应急页不沿用面板的 `RESET` 确认词（两场景机制相互独立，见 3.4.8）。**存储与校验**：操作码仅存进程内存（应急模式启动时生成并打印日志，不落库）——数据库损坏场景同样可校验；应急页提交时与内存值比对；容器重启后操作码变更（重新从运行日志获取）

**应急页能力**：

1. **重置管理员密码**（仅环境变量触发且数据库可读时提供）：选择管理员账号 → 设置新密码（复杂度 ≥8 字符）→ 确认后更新密码；完成后**进程退出（exit）**，由 docker compose 的 restart 策略拉起——**变量未移除则再次进入应急模式（可预期的循环）**，页面提示「已从 docker-compose 移除 `RESET_ADMIN_PASSWORD` 环境变量并重启容器」；移除变量重启后恢复正常服务；**用户表为空时无任何账号可选，此能力不可用，仅可重新初始化**；**仅对设有本地密码的账号有效——纯 OIDC 管理员（无密码哈希）重置后仍无法本地登录，此类账号的救援路径：恢复服务后由其他管理员「清除 OIDC 绑定 + 设置密码」，或直接重新初始化**
2. **重新初始化（应急全清）**：一键清空所有数据回到 Setup（**输入一次性操作码 + 二次确认**，与面板危险操作区的 `RESET` 确认词相互独立，见 4.8）——**数据库可连接时以 SQL 清空；数据库无法打开/损坏时降级为删除数据库文件 + 版本文件目录 + /public 资源后重建空库**（两种路径均回到未配置状态）——数据库损坏/认证死锁/配置错乱时的最后手段；**自动触发的应急页仅保留此按钮**；**全清完成后与重置密码一致：进程退出（exit）**——重启后变量已移除则正常进入 Setup 首次配置，未移除则再次进入应急模式（可预期循环）

**设计要点**：

- **能力分级（安全收紧）**：重置管理员密码仅由环境变量门控（手动触发）；自动触发（数据库损坏/关键配置损坏）的应急页仅保留重新初始化按钮，降低无凭据重置任意管理员密码的安全隐患；环境变量已设置但数据库不可读时，页面自动降级为仅重新初始化（重置技术上不可执行）
- 应急页无需登录（正常认证体系可能已不可用）
- **应急端点仅在应急模式下暴露，正常运行时屏蔽（不注册路由）**；应急模式为极低频救援场景且正常服务已暂停，不额外加限流/验证码防护，保持最简
- **部署提示：应急模式期间建议断开公网**（应急页的「重新初始化」为破坏性操作，避免公网意外访问触发，见 7.1）
- 运行日志输出警告：应急模式已触发（含触发原因）/ 重置已执行 / 等待移除环境变量重启；**并输出一次性操作码（应急页操作前须输入，页面不公开）**
- **自动触发检测时机**：启动时执行数据库完整性检查（`PRAGMA integrity_check`）与关键配置校验；运行中检测到关键查询失败（如 `SQLITE_CORRUPT`）时进程退出（exit），由 compose restart 策略拉起后进入应急模式
- **应急期间的下载服务**：全部正常服务端点（含订阅/规则/分享下载）返回 503——客户端自动更新暂停，恢复服务后自动继续，**下载链接本身不失效**（Token 未受影响）
- **重置管理员密码成功后递增该管理员凭据版本号**（其全部现有会话立即失效，与 4.6 密码重置语义一致）
- 环境变量每次启动均生效（不做一次性标记，保持简单）；**部署文档提供操作示例：重置/全清完成后进程退出（exit）→ compose restart 自动拉起 → 移除 `RESET_ADMIN_PASSWORD` 变量后重启恢复正常服务；变量未移除则再次进入应急模式（可预期循环）**
- **compose 模板约定**：restart 策略用 `unless-stopped`，healthcheck 仅作状态展示（应急时 unhealthy），不配置任何由健康检查触发的重启动作——应急模式的 exit + 自动拉起循环不会演变为重启风暴

## 四、核心机制设计（重构重点）

### 4.1 版本管理（统一适用于订阅/规则/自定义订阅/分享订阅，四类资源能力一致——含文本编辑创建新版本）

**版本模型**：每种内容资源维护一个版本列表，每个版本包含：版本号、文件引用、创建时间、更新时间。当前激活版本通过「当前」指针指向具体版本。

**统一规则**：

- 版本号 = 已有最大编号 + 1（不可用「列表长度 + 1」，防止删除版本后编号冲突）
- 最多保留 5 个版本，超出自动删除最旧的（文件 + 记录）
- 不可删除最后一个版本；**不可删除当前激活版本（须先切换到其他版本）**
- 上传新版本 / 编辑当前版本内容保存 → 自动创建新版本号并切换为当前（**文本编辑保存前对内容做 YAML 语法提示，不阻断保存，预览仍可人工检查**；该规则对四类资源统一适用）
- 切换当前版本时更新该版本时间戳（用于首页更新时间戳计算）；**时间戳口径：以最近一次切换动作/内容变更时间为准（切回旧版本也刷新该时间），首页始终反映「分发内容最近变动」；不按被指向版本自身的历史时间取值**
- **时间统一 UTC 存储**，前端按本地时区展示（版本时间戳、访问日志、审批申请时间等）
- 删除资源 → 级联删除其全部版本文件

**并发安全**（关键设计）：

- 版本号计算与版本列表更新必须在**单个事务 + 写锁**内完成（SQLite 为库级写锁：事务内 UPDATE 即持锁，并发上传自然串行化），防止并发上传导致版本号冲突或文件覆盖
- 「当前」指针切换采用**原子替换**（临时指针 + rename），避免下载过程中读到半切换状态；**要求部署卷支持符号链接（主流 Docker volume/bind mount 均支持，部署文档注明该要求）**
- 所有资源类型的版本创建路径统一失败清理模式（创建记录 → 写文件 → 更新列表，任一步失败完整回滚清理）

### 4.2 下载 Token 体系（三类独立）

| Token 类型 | 绑定关系 | 生命周期 | 主要操作 |
|-----------|---------|---------|---------|
| **用户下载 Token** | 用户 + 平台 + **可选标识**（custom_sub_id / subscription_id，互斥且可不填，见三态模型） | 长期有效，无过期时间 | 首次获取时自动生成并复用；用户点击「刷新链接」刷新；管理员吊销全部；用户被删除/禁用时**物理删除**；自定义订阅上传/删除时按下文级联规则；角色降级时清除显式 Token |
| **分享 Token** | 分享订阅 | 长期有效 | 创建时自动生成；管理员刷新（旧失效）或吊销（**物理删除记录** + token_status 标记，内容保留） |
| **规则 Token** | 规则（**全局共享，不绑定用户**） | 长期有效 | 创建时自动生成；管理员刷新（旧失效）；**任何持有链接者均可下载，不随用户禁用/删除失效** |

**用户下载 Token 三态模型**（用户组分发核心）：

- **无标识 Token（组解析）**：绑定 用户+平台，复用键 user+platform。下载时实时解析「用户所属组 → 组在该平台的选定订阅 → 返回内容」；组级切换选定/用户换组/删组迁入均**无感自动生效且永不越权**（实时解析始终返回当前权限对应内容）
- **自定义订阅 Token**：绑定 用户+平台+custom_sub_id，复用键 user+platform+custom_sub_id。直接返回该自定义订阅内容，不受组分配影响；**上传/覆盖自定义订阅时删除该用户在该平台原有的无标识 Token**（旧链接立即失效，见 2.3）
- **显式订阅 Token（管理员预览）**：绑定 用户+平台+subscription_id，复用键 user+platform+subscription_id。直接返回指定订阅内容，不受组分配影响；**下载端点实时校验持有人当前仍为管理员**；管理员降级（admin→user）或订阅删除时级联清除（见 2.5）

**Token 生命周期联动**（保证分级不被绕过）：

- 组级切换选定订阅 / 用户换组 / 删组迁入 → **无需清 Token**（无标识 Token 下载时实时解析组选定，订阅内容更新对客户端无感）
- 上传/覆盖自定义订阅 → 清除该用户在该平台的无标识 Token（旧链接立即失效，见 2.3）
- 删除订阅 → 级联清除指向它的 Token（含管理员显式预览 Token）+ 清除所有组关联与选定；存量无标识 Token 下载时解析到空 → 返回错误（访问日志记录原因 `unassigned`），待管理员重新选定
- 删除用户自定义订阅 → 清除 custom_sub_id 指向的 Token，用户下次访问首页重新生成无标识 Token
- 角色降级（admin→user）→ 清除其全部显式订阅 Token（见 2.5）
- 删除用户 → 清除其全部 Token 与自定义订阅
- 账号禁用 → **同一事务内递增该用户 credential_version（其全部现有会话立即失效）并物理删除其全部 Token 记录**（防竞态窗口内旧 Token 仍可下载）；重新启用后**不恢复原 Token**，用户下次访问首页重新生成
- **Token 并发首建**：首次生成采用**唯一索引 + 冲突重试**（复用键 user+platform[+标识] 建唯一索引，并发请求下 ON CONFLICT 复用既有 Token，见 5.3）

### 4.3 订阅内容下载分发

**统一输出行为**：所有下载端点始终以纯文本（`text/plain`）输出订阅配置内容（类似 GitHub RAW），VPN 客户端可直接读取。

**平台附加响应头（平台级可配置）**：每个平台可配置一组附加响应头（键值对列表），该平台订阅下载时随响应额外返回，用于客户端专属兼容（取代原 Clash Verge 硬编码逻辑）：
- 平台创建/编辑时可增删改附加响应头（可选，可为空）；头值支持 `{frontend_url}` 占位符，下载时替换为当前前端地址
- **默认平台 clash-verge 预置三条**：`Content-Disposition: attachment; filename*=UTF-8''...yaml`（客户端依赖识别文件名）、`profile-update-interval: 300`（建议每 300 分钟自动更新）、`profile-web-page-url: {frontend_url}`（用户可跳转到管理页面）；其余默认平台预置为空
- 自建平台默认无附加头，管理员可按需配置

**四种下载途径**：

| 途径 | 认证方式 | 用途 |
|------|---------|------|
| 会话凭据下载 | Bearer 会话凭据 | Web UI 预览订阅内容（浏览器直接查看）；管理员可指定订阅 ID 预览池内任意订阅；**非管理员传 subscription_id 一律忽略**（返回组选定内容） |
| 用户 Token 下载 | `?token=` 查询参数 | VPN 客户端实际使用（无需登录）；Token 指向自定义订阅时返回自定义内容 |
| 分享 Token 下载 | `?token=` 查询参数 | 分享订阅公开下载（无需登录） |
| 规则 Token 下载 | `?token=` 查询参数 | 规则公开下载（无需登录） |

**设计要点**：

- 下载时始终返回「当前」指针指向的最新版本
- 所有下载端点返回**禁止缓存**响应头（`no-store` 等），确保客户端每次拉取最新配置
- 所有下载端点受速率限制并记录访问日志（含成功/失败状态与失败原因）
- 会话凭据路径与 Token 路径互斥使用，不会同时出现两种凭据
- **无效/过期 Token 统一返回 404**（不泄露资源存在性），访问日志记录失败原因 `token_invalid`；规则/分享 Token 为公开资源（见 4.2）；**下载端点的业务错误（如 `unassigned`）同样以纯文本注释块输出（如 `# error: unassigned`），不返回 JSON/HTML，防客户端将错误响应误解为配置内容**

### 4.4 级联删除规则（数据一致性）

| 删除对象 | 级联范围 |
|---------|---------|
| 用户 | 该用户全部下载 Token + 自定义订阅（含版本文件）；密码重置令牌随 1 小时 TTL 自然过期（无需级联清理） |
| 上传/覆盖自定义订阅 | 该用户在该平台的无标识（组解析）Token（旧链接立即失效，见 2.3） |
| 自定义订阅 | custom_sub_id 指向的下载 Token（用户下次访问首页重新生成无标识 Token） |
| 角色降级（admin→user） | 该用户全部显式订阅 Token（见 2.5） |
| 订阅（订阅池内某份） | 指向它的下载 Token（含管理员显式预览 Token）+ 所有组的关联与选定；受影响组置空**不回退**（组内用户显示「未分配」）；**删除事务内将受影响组置轻量标记（needs_reselect），组管理页据此高亮并提供「重新选定」快捷入口，重新选定后标记清除**（见 3.4.2） |
| 规则 | 该规则的下载 Token + 版本文件 |
| 分享订阅 | 分享 Token + 版本文件（吊销=**物理删除** Token 记录 + token_status 标记，见 3.4.3） |
| 平台 | 该平台全部订阅（含版本文件）+ 相关下载 Token + 自定义订阅（含版本文件）+ 所有组在该平台的关联与选定 + 安装包文件；需二次确认（**确认对话框逐项列出影响清单：N 份订阅、M 个 Token、K 份自定义订阅，并提示文件不可恢复**）；受影响组同事务置轻量标记，**组管理页据此高亮并提供「重新选定」快捷入口** |
| 用户组 | **不做级联删除**：组内用户自动迁入默认组（Token 无需清理，实时解析自动跟随）；默认组不可删 |
| 取消订阅-组关联 | 若该组正在选定此订阅 → **拒绝操作**，提示先去组管理改选（防悬空选定） |

### 4.5 更新生效链路

管理员上传新版本（自动切换为当前）→ 首页更新时间戳更新 → VPN 客户端按更新间隔自动拉取（或用户手动刷新链接）→ 客户端通过 Token 实时解析获取最新「当前」版本内容 → 全员自动生效，无需重新分发链接；组级切换选定订阅同样经实时解析无感生效。

### 4.6 账号与认证机制（本地用户体系）

**用户身份模型**（登录能力由**是否设有密码**决定，不依赖认证来源列）：

| 用户类型 | 登录标识 | 密码 | 登录方式 |
|---------|------|------|---------|
| OIDC 用户（未设密码） | oidc_subject（user_id 内部稳定） | 无 | 仅 OIDC |
| OIDC 用户（已设密码） | oidc_subject（user_id 内部稳定） | bcrypt 哈希 | OIDC 或 邮箱+密码 |
| 本地用户（管理员创建） | 邮箱（user_id 内部系统生成） | bcrypt 哈希 | 邮箱+密码 |
| 自注册用户 | 系统生成 | bcrypt 哈希 | 邮箱+密码（激活受自注册审批开关控制，见 2.6） |

**邮箱唯一性与身份绑定**：

- 邮箱全局唯一约束（**NULL 除外**——OIDC 未返回 email 时允许创建用户，email 可空，多个无邮箱用户可并存，见 2.7）；本地登录以邮箱为唯一标识
- **无邮箱用户边界**：无邮箱的 OIDC 用户无本地登录/密码重置/自动合并能力（无法按邮箱匹配），UI 标注「无邮箱」；管理员可在用户管理手动补填邮箱后获得相应能力（见 3.4.5）
- **自动合并绑定（仅当 OIDC 返回 `email_verified=true` 且返回邮箱非空，且目标邮箱账号未绑定其他 OIDC 身份、状态为待审批/已激活）**：OIDC 登录时，若 subject 对应用户不存在但邮箱已被占用且已验证 → 视为同一用户，自动合并并绑定 OIDC 身份（**将 subject 写入该用户 oidc_subject 列，user_id 保持内部稳定不变**）；**邮箱未经验证/未返回、目标账号已绑定其他 OIDC 或账号已禁用时不做自动合并**，提示冲突，防止账号接管（与单绑定规则一致）。**合并与审批的交互**：自动合并属于**识别已有用户**——不产生新用户、**不触发 OIDC 审批/白名单流程**；合并后自动激活账号（因用户已通过 OIDC 认证，无需再走审批流程），激活后可用 OIDC 或本地登录（**已确认取舍：自动合并可激活「待审批」账号，即 OIDC 认证视同可信、可绕过自注册/审批流程，文档明示此行为**，见决策 #118）
- **手动绑定**：自注册/本地用户在个人中心点击「绑定 OIDC」→ 跳转 OIDC 授权 → 回调校验该 OIDC subject 未绑定其他账号 → 绑定到当前账号（绑定基于 subject，不要求邮箱一致）；绑定后可用 OIDC 或邮箱+密码登录同一账号
- **单 OIDC 绑定**：每个账号最多绑定一个 OIDC 身份（subject）；已绑定账号遇到其他 OIDC 登录（subject 不同）→ 不覆盖现有绑定，提示冲突
- 管理员创建本地用户 / 自注册时邮箱被占用 → 明确提示冲突（与登录防枚举的取舍为**有意为之**：注册/创建环节需向用户反馈冲突，登录环节不泄露存在性）
- **OIDC 登录同步策略**：username 在**每次 OIDC 登录时刷新为提供商最新值**（展示用；个人中心手动修改的 username 会被下次 OIDC 登录覆盖，见 3.6）；email 在**首次创建时写入后不自动覆盖**（与下条「OIDC 侧改邮箱边界」一致）
- **邮箱规范化**：所有写入入口（注册/管理员创建/补填/OIDC 返回）统一 **trim + 小写化**后存储；唯一约束与自动合并匹配均基于规范化后的值
- **OIDC 侧改邮箱边界**：OIDC 用户在提供商侧修改邮箱后，本地「邮箱+密码」登录的邮箱不同步（本地邮箱仍为绑定时的值）；如需本地登录请通过个人中心/管理员同步修改邮箱

**账号状态流转与启用**（两个独立审批开关，均默认关闭）：

- 自注册 → 受自注册审批开关控制——关闭（默认）→ **直接激活**；开启 → **待审批** → 管理员审批 → **已激活** / **拒绝（即删除账号，邮箱释放可重新注册，被拒用户可再次注册进入审批队列，滥用由注册限流+验证码兜底）**（用户表为空时首个自注册者免审批直接成为管理员，不受审批开关影响）；**注册提交后显示「注册成功，等待管理员审批」提示页**
- OIDC 首次登录：受 OIDC 审批功能开关控制——关闭（默认）→ **直接激活**（白名单不生效）；开启 → 白名单命中 → **已激活**，未命中（白名单非空）→ **待审批** → 审批中心处理；白名单未配置或为空 → 直接激活；**未命中白名单进入待审批时中转页显示「账号待审批」提示页，不签发会话；待审批用户重复 OIDC 登录/重复注册显示「已提交，等待审批」，不重复创建记录**
- 用户表为空时，首个登录/注册者始终直接激活并成为管理员（不受开关影响）
- 待审批用户从未获得会话，不存在下载 Token，审批通过/拒绝无需特殊 Token 清理逻辑
- 管理员可禁用/启用任意非管理员账号（**管理员可禁用自己，但会话立即失效即登出**）：禁用后不可登录，会话（凭据版本号机制，见 5.4）与下载 Token 一并失效（**同一事务内递增凭据版本号 + 物理删除其全部 Token 记录**）；重新启用后 Token 不恢复，用户下次访问首页重新生成
- **禁用管理员保护**：允许禁用管理员账号，但禁止禁用最后一个活跃（未禁用）管理员（系统内活跃管理员数必须 ≥ 1，防管理面锁死）；被怀疑滥用的管理员可由其他管理员禁用或删除（删除受「最后一个管理员」保护约束）
- **修改邮箱**成功后递增该用户凭据版本号，所有设备旧会话立即失效（与「修改后需重新登录」一致）
- **密码重置**（管理员直接重置/邮件重置完成/个人中心自助修改）成功后递增该用户凭据版本号，其全部现有会话立即失效（适用于账号疑似被盗用场景）
- 仅「已激活」账号可登录

**验证码机制**（reCAPTCHA / Cloudflare Turnstile）：

- 面板配置：提供商 + 站点密钥 + 服务端密钥 + 启用页面勾选（注册/登录/找回密码，默认全不选）
- 前端在勾选页面渲染验证码组件；后端对受保护接口校验验证码 token（服务端调用提供商验证接口）
- 未配置密钥或未勾选页面 → 跳过校验（本地开发不受阻）

**密码重置令牌机制**（本地账号）：

- 一次性令牌，1 小时有效，用后即删；管理员触发与用户自助触发共用同一机制
- 无论邮箱是否存在，响应一致（防枚举）
- 批量能力：管理员可为所有无密码用户生成重置链接并发送邮件（用于 OIDC 断开后的存续；**无邮箱用户无法接收邮件，自动排除并提示**）
- **SMTP 未配置或发送失败不阻断主流程**：业务操作（审批/重置等）仍正常完成，记录错误日志并在 UI 提示「邮件发送失败」

**会话时长**：

- 「记住我」勾选 → 会话 7 天；不勾选 → 24 小时；过期后需重新认证
- OIDC 与本地登录的会话凭据格式统一（同一套签发/验证机制）

**OIDC 断开后的用户存续**（仅管理员手动触发——清空/移除 OIDC 配置，系统不自动判定）：

- OIDC 重定向登录失效；已设本地密码的用户不受影响，仍可邮箱+密码登录
- 未设密码的 OIDC 用户暂时无法登录 → 管理员可为其设置密码（自动发送重置邮件），或使用批量操作
- 纯本地模式不存在此场景（无 OIDC 依赖）

### 4.7 软件安装包与路径分级

**客户端安装包分发**（平台级）：

- 每个平台支持**两种下载来源并存**：本地上传文件（二进制/压缩包，≤300MB）+ 外部下载链接
- 本地上传文件**公开下载**（无需登录），存储于可缓存路径，可被 CDN 缓存；上传新文件即覆盖（文件名带时间戳，URL 变化以突破 CDN 旧缓存；**覆盖时同步删除旧时间戳文件**，避免数据卷无限膨胀；**上传/覆盖/删除旧文件走平台级写锁 + 事务**（事务内 UPDATE 持锁串行化，同版本管理事务模板（见 4.1），防并发上传互删文件）
- 首页「下载客户端」按钮：有本地文件 → 「本地下载」；有外部链接 → 「链接下载」；两者都有 → 显示两个按钮
- 删除平台时级联删除其安装包文件
- **安装包下载为公开静态资源，不记访问日志、不限流**（由 CDN/反代缓存承载，区别于订阅下载）

**路径分级与缓存策略**（避免缓存不一致）：

| 路径 | 内容 | 缓存策略 |
|------|------|---------|
| `/public/*` | 站点图片（logo/favicon）、平台安装包 | **可缓存**（public + max-age） |
| `/assets/*` | 前端构建产物（文件名含哈希） | immutable（长期缓存） |
| 订阅/规则/分享下载端点 | 订阅配置内容 | **禁止缓存**（no-store 等，保持每次拉取最新） |

**站点品牌资源**：站点 ICON/logo 上传后存至 `/public/site/` 固定路径（覆盖即更新），由前端页面引用（**引用带版本参数如 `?v=更新序号`，避免 CDN/浏览器缓存旧图**）。

### 4.8 运行日志、实时日志流与数据清理

**分级运行日志**（与访问日志区分）：

- 运行日志输出到 stdout（docker compose logs 可见），级别：debug / info / warn / error
- 环境变量 `LOG_LEVEL` 提供初始级别（默认 info）；**面板配置可运行时切换**（持久化到配置存储，立即全局生效，无需重启）
- 与「调试模式开关」（5xx 错误响应是否返回内部详情）独立：日志级别控制输出详细度，调试开关控制错误响应内容，二者可独立配置

**实时日志流（SSE 单向流）**：

- 运行日志经统一日志管道同时输出到 stdout 与**内存环形缓冲**（如最近 500 条）
- 管理面板通过 SSE 端点订阅：先推送缓冲历史，再实时推送增量；客户端自动重连；连接断开自动清理订阅
- **认证方式：一次性短期 Token**（EventSource 原生 API 不支持自定义 Header）：前端先通过现有会话凭据（Authorization Header）向后端换取一次性短期 Token，再将该 Token 作为 `?token=` 查询参数用于 EventSource URL；响应 `no-cache`。**重连语义**：Token 单次连接建立后即删除（严格一次性）；前端检测到连接断开时重新走会话凭据换取新 Token 再重连；已换取但未使用的 Token 按短 TTL（如 5 分钟）过期自动清理。此方案避免会话凭据经 URL 传递暴露于反代/中间代理访问日志
- **并发订阅上限**（如 5 个连接），超出拒绝新连接并提示（防资源耗尽）
- 仅管理员可订阅（实时日志暴露内部信息）；支持按级别过滤（前端过滤即可，保持简洁）
- 与访问日志（access_logs 持久化业务记录）明确区分：实时流 = 运行日志（HTTP 请求/响应、错误、调试），不落库

**数据清理**：

- **清空日志**：删除全部访问日志记录（二次确认）；实时日志缓冲为内存态，随清空/重启自然重置
- **一键清空所有数据**（确认词 + 二次确认）：清空全部业务数据（用户/**用户组**/订阅/平台/规则/分享/自定义订阅/各类 Token/访问日志/认证状态/密码重置令牌）+ 系统配置（含签名密钥、configured 标记）+ 数据文件（版本文件、/public 资源）→ 系统回到**未配置状态**，**无需重启**（前端路由守卫检测 configured=false 自动进入 Setup 首次配置，重新生成密钥；管理员由首个完成认证的用户重新产生，重新初始化时预置默认组与 3 个默认平台，见 2.5）；实时日志缓冲同步重置；**无需重启的原因与内存态复位**：面板全清在服务健康时执行，密钥与配置已在库内重置（旧会话凭据因密钥轮换验签失败自然失效），同时同步复位内存态——启动时缓存的配置（如前端地址）、SSE 连接与 SSE 短期 Token、限流计数、实时日志缓冲；应急「重新初始化」因可能伴随数据库损坏/文件删除，改以进程退出重启保证干净重建（两路径差异见 3.8）；**数据库无法打开时**（应急场景）降级为删除数据库文件 + 数据文件后重建空库（见 3.8）
- 清空操作为破坏性操作，执行前必须确认词校验（防误操作）；**执行顺序：先清库（事务）再删数据文件；文件删除失败记录错误日志并在 UI 提示，不阻断回到 Setup 状态**

### 5.1 技术选型

> 以下选型在现有系统已验证可行（纯静态编译、零 CGO、小体积、低成本维护），重构时作为推荐基线；如无充分理由不建议更换。

### 5.2 模块划分（逻辑分层）

> 重构时建议保持清晰的职责分层，但命名与文件组织可重新设计（不绑定旧命名）。

```
接入层（HTTP）
  ├── 公开端点：健康检查、系统状态、公告（**数据接口公开，无敏感信息；UI 仅登录后首页展示**，见 3.3）、规则下载（Token）、分享下载（Token）、/public 静态可缓存资源（图片/安装包）、应急恢复页（应急模式下，见 3.8）
  ├── 认证端点：OIDC 登录/回调、本地登录、注册、忘记/重置密码、绑定 OIDC、当前用户（**限流仅作用于表单类端点：本地登录/注册/找回密码；验证码同范围**；OIDC 回调与当前用户端点不限流）
  ├── 用户端点：首页平台数据、更新时间、刷新 Token、个人中心（需会话）
  ├── 订阅下载：会话预览 / Token 下载（限流 + 防缓存）
  └── 管理端点：用户/订阅/用户组/分享/平台/规则/审批中心/面板配置/日志（含实时日志流 SSE、清空日志、一键清空数据）（需会话 + 管理员）
        │
业务层（领域服务）
  ├── 认证服务：OIDC 流程（含模拟 OIDC）、PKCE、本地登录（bcrypt）、自注册、验证码校验、OIDC 绑定、密码重置、会话签发/验证
  ├── 用户服务：用户管理、管理员保护、分组调整、账号状态管理
  ├── 审批服务：待审批用户列表、激活/拒绝、通知触发
  ├── 订阅服务：订阅池 CRUD（含组关联管理）、版本管理、用户 Token 生成/复用/刷新
  ├── 用户组服务：组 CRUD、关联订阅管理、每平台选定订阅、删组迁入默认组
  ├── 自定义订阅服务：覆盖分配、版本管理、Token 联动
  ├── 分享订阅服务：分享 CRUD、版本管理、Token 刷新/吊销
  ├── 规则服务：规则 CRUD、版本管理、Token 刷新
  ├── 平台服务：平台 CRUD、安装包上传/删除
  ├── 系统配置服务：OIDC/白名单/本地认证开关/审批开关/验证码/SMTP/站点信息/限流/日志级别/公告/调试开关
  ├── 邮件服务：SMTP 发送（按勾选范围：密码重置 / 审批通知 / 欢迎邮件）
  ├── 日志服务：访问日志写入与查询、运行日志管道（分级输出 + 环形缓冲）、实时日志流广播（SSE）
  └── 数据清理服务：清空访问日志、一键清空所有数据（完全重置）
        │
数据层（持久化）
  ├── 配置存储（键值）
  ├── 业务存储（用户/用户组/平台/订阅/规则/分享/自定义订阅）
  ├── 令牌存储（用户 Token/分享 Token/规则 Token）
  ├── 密码重置令牌存储（一次性令牌，1 小时 TTL）
  ├── 日志存储（访问日志）
  └── 认证状态存储（OIDC state，TTL 过期清理）
```

**职责约束**：接入层只做协议解析与响应；业务层承载规则（分级、覆盖、级联、版本）；数据层封装 SQL 与文件读写。接入层不直接操作存储，业务层不感知 HTTP。

### 5.3 数据实体设计（实体关系）

> 实体名与字段名可重新设计；以下为**功能需求层面**的实体清单与关系语义。

| 实体 | 关键属性 | 关系语义 |
|------|---------|---------|
| 系统配置 | 键值对 | 承载：认证参数（含加密密文）、OIDC 白名单、本地认证开关、验证码参数、SMTP 参数与启用范围、站点信息、运行模式、日志级别、签名密钥、限流参数、公告内容、系统状态标记、调试开关 |
| 用户 | 标识（内部稳定）、oidc_subject（OIDC 身份，唯一可空）、用户名（无唯一约束）、邮箱（唯一，NULL 可空）、角色、所属组（单组互斥）、密码哈希、来源、状态、凭据版本号（会话失效机制，见 5.4） | 1:N 用户下载令牌；1:N 自定义订阅；1:N 密码重置令牌 |
| 用户组 | 标识、名称（全局唯一）、是否预置默认组 | M:N 订阅（关联）；每平台选定一份订阅；1:N 用户 |
| 订阅-组关联 | 订阅、用户组 | 多对多关联表；取消关联时校验悬空选定（见 4.4） |
| 组选定 | 用户组、平台、订阅 | 每组每平台至多一份；组级统一选定（见 2.2） |
| 平台 | 标识、名称、描述、客户端 scheme 列表、附加响应头（键值对列表，含 {frontend_url} 占位符，见 4.3）、安装包文件引用、外部下载链接 | 1:N 订阅池订阅；初始化预置 3 个默认平台（clash-verge 预置附加响应头） |
| 订阅 | 标识、名称、平台 | 订阅池内同平台可多份；M:N 用户组；1:N 版本；标识与分享订阅/规则/自定义订阅共用全局唯一命名空间（见 2.2） |
| 版本 | 版本号、文件引用、创建/更新时间 | 所有内容实体共享的版本列表；「当前」指针指向激活版本 |
| 自定义订阅 | 标识（**自动生成**，与订阅/分享/规则共用全局唯一命名空间，见 2.2）、用户、平台 | 用户+平台唯一；1:N 版本；优先级高于组分配 |
| 分享订阅 | 标识（**自动生成**，与订阅/分享/规则共用全局唯一命名空间，见 2.2）、名称、token_status（有效/已吊销） | 1:N 版本；0:1 有效分享令牌（吊销=物理删除令牌 + 置位标记，见 3.4.3） |
| 规则 | 标识、名称、客户端类型、客户端 scheme 列表 | 1:N 版本；1:N 规则令牌；标识与订阅/分享订阅/自定义订阅共用全局唯一命名空间 |
| 用户下载令牌 | 令牌值、用户、平台、可选标识（custom_sub_id / subscription_id，互斥且可不填） | 三态解析见 4.2：无标识=实时解析组选定；custom_sub_id=自定义内容；subscription_id=显式订阅（需校验管理员）；复用键：无标识 user+platform；自定义 user+platform+custom_sub_id；显式 user+platform+subscription_id |
| 分享令牌 | 令牌值、分享订阅 | 每分享订阅至多一份有效令牌，可刷新；吊销=物理删除记录 |
| 规则令牌 | 令牌值、规则 | **全局共享（不绑定用户）**，每规则一份，可刷新 |
| 认证状态 | state 值、PKCE 验证器、创建时间 | 10 分钟 TTL，用后即删 |
| 密码重置令牌 | 令牌值、所属用户、过期时间、使用标记 | 一次性；1 小时 TTL；用后即删 |
| 访问日志 | 用户（可空）、IP、下载类型、平台、资源标识、状态、失败原因、时间 | 按日期查询；90 天自动清理 |

**关键约束**：内容实体的版本列表与「当前」指针更新必须事务化（见 4.1）；令牌的创建/轮替/吊销/级联清除必须原子（见 4.2/4.4）。

### 5.4 认证与安全架构

- **会话凭据最小化**：仅含用户标识 + **凭据版本号** + 标准声明（签发/过期时间）；角色、组归属等权限**不入凭据**，每次请求实时查库。**会话立即失效机制**：禁用/删除账号、修改邮箱、密码重置（管理员重置/自助修改完成）时递增该用户凭据版本号，请求时查库比对，版本不符即返回 401——保证「禁用账号会话一并失效」等场景，符合实时查库原则；**一键清空数据**时不依赖版本号：签名密钥随全清删除并重新生成，旧凭据验签必然失败而自然失效
- **权限校验链**：会话验证（解析凭据 → 查库取用户）→ 管理员校验（仅管理端点）；两个中间件独立、可组合
- **凭据存储**：浏览器本地存储（非 Cookie），API 通过 Authorization 头传递；**前端配置 CSP 基线**（允许 reCAPTCHA/Turnstile 验证码脚本外链，其余资源收紧），缓解 localStorage 凭据的 XSS 窃取面
- **下载令牌**：仅通过查询参数传递，不进入日志（自动脱敏）；显式订阅 Token 下载端点**实时校验持有人当前仍为管理员**（防降级后越权，见 4.2）

### 5.5 内容文件存储设计

- 全部版本文件按内容域分目录存放：订阅 / 规则 / 自定义（按用户+平台隔离）/ 分享
- 每个版本独立文件（`v1`、`v2`…），「当前」为指向激活版本的符号指针（原子替换切换）
- **可缓存静态资源**存放于 `/public` 目录：站点图片（logo/favicon）、平台安装包（文件名带时间戳以突破 CDN 缓存）
- **数据库按运行模式分离**：Dev 与 Production 使用不同数据库文件（如 `app-dev.db` / `app-prod.db`），启动时按 `APP_MODE` 选择对应文件（不在运行时切换）；**模式隔离仅限数据库文件；版本文件目录与 `/public` 静态资源（站点图片、安装包）两模式共享、不按模式分离**——Dev 上传的安装包/图片切回 Production 后仍可访问（Dev 定位临时调试，已确认取舍）；**模式切换时数据不迁移**（Dev 定位临时调试，数据不需长期保留）
- 所有用户可控路径必须经过路径穿越防护（禁止 `..` 与绝对路径逃逸）
- 统一存放于持久化卷（与数据库同卷，便于整体备份）

### 5.6 部署架构

```
用户浏览器 ──HTTPS──▶ 外部反向代理（TLS 终止）
                        └─ /* → 127.0.0.1:8080（单容器）
                              ├─ API 路由
                              ├─ /assets + /public 静态资源（缓存策略见 4.7）
                              └─ 其余路径 → 前端入口（SPA 回退）
                                      │
                              持久化卷
                    ┌───────┬──────┬──────┬────────┐
              数据库×2 订阅文件 规则文件 分享文件 /public
```

- **单容器**：后端同时服务 API + 静态资源（前端产物 + `/public` 可缓存资源）+ SPA 回退；对外只暴露一个端口
- **端口隔离（按接入方式）**：外部反代接入时容器端口仅绑定本机回环地址（`127.0.0.1`），不直接暴露公网；局域网直连模式由部署者直接映射端口，网络边界由部署者自行控制（防火墙/内网）
- **单数据卷**：数据库与全部内容文件统一持久化，备份即打包该卷
- **部署向导提供两种接入方式的 compose 模板**（回环绑定 `127.0.0.1:8080:8080` / 局域网直连 `8080:8080`，带注释，见 7.1）
- **环境变量**：`APP_MODE`（dev/prod，启动时决定）+ `TRUST_PROXY`（auto/on/off，默认 auto = 信任回环 + 私有网段来源转发头，见 6.4）+ 监听端口、日志级别、日志格式可选覆盖；业务配置一律走 Web UI

## 六、安全设计

### 6.1 认证安全

- OIDC 登录采用 PKCE（验证器与 state 绑定持久化），防授权码截获
- state 三重校验（Cookie == 回调参数 == 持久化记录）+ 用后即删，防 CSRF 与重放
- 本地密码 **bcrypt 哈希**存储，绝不落明文
- 会话凭据有效期：记住我 7 天 / 非记住我 24 小时；过期后需重新认证
- 本地登录 / 自注册 / 忘记密码端点均受速率限制；失败与不存在提示统一措辞（防邮箱枚举）
- **验证码**：reCAPTCHA / Turnstile 服务端校验（按管理员勾选的页面启用，未配置跳过）；**仅适用于可访问外网的部署**，前端脚本加载失败时显示明确错误提示（见 3.2）
- 密码重置令牌：一次性、1 小时有效、用后即删；响应不区分邮箱是否存在
- **OIDC 测试连接含客户端凭据校验**（client_credentials 换 token 验证 Client ID/Secret，不支持时降级为警告），确保 Setup 阶段即可发现密钥错误（见 3.1）
- 仅「已激活」账号可登录（待审批 / 已禁用拦截）；禁用账号的会话与 Token 一并失效
- 认证端点速率限制独立配置：登录（默认 10/分钟）、注册（默认 5/分钟）、找回密码（默认 5/分钟）

### 6.2 密钥与凭据存储

- 签名密钥在 Setup 时**自动随机生成**，不硬编码、不依赖 .env
- 敏感配置（认证 Client Secret）以 **AES-256-GCM 加密**后落库；加密密钥由签名密钥派生（单一密钥管理，无需额外配置）
- SMTP 密码同样以 AES-256-GCM 加密落库（复用同一密钥派生逻辑，不新增密钥管理复杂度）
- 若配置存储与令牌存储被清空（一键清空所有数据，见 4.8），全部会话与令牌立即失效（安全兜底）

### 6.3 输入与路径安全

- 所有含用户输入的路径操作经路径穿越防护（防 `..` 逃逸）
- 资源标识格式校验（小写字母数字连字符）；订阅/分享订阅/规则/自定义订阅标识**共用全局唯一命名空间**（四类资源创建时交叉校验冲突；**分享/自定义订阅标识由系统自动生成**，见 2.2）
- 文件上传大小分档限制：订阅/规则/自定义/分享文件 ≤50MB；**安装包 ≤300MB**（前端 + 后端双重校验；安装包上传需**流式落盘**避免整读内存；外部反代 `client_max_body_size` 需相应调大）；**文件扩展名不做白名单限制**——上传内容属管理员自主控制范围，安全边界由使用者自行把握（不过度防御原则）
- 管理端点全部要求管理员权限（会话校验 + 角色校验双层）

### 6.4 下载安全与防滥用

- 下载认证仅凭令牌（用户/分享/规则三类独立），令牌无过期时间但可轮替/吊销
- **缓存分级**：订阅/规则/分享下载响应返回**禁止缓存**头（`no-store` 等），防止代理缓存旧配置；`/public` 静态资源（图片/安装包）返回**可缓存**头，供 CDN 加速（见 4.7）
- 订阅/规则/分享下载端点统一速率限制（默认 20/分钟，**按 IP 维度**计数；**NAT/反代共享 IP 场景多客户端自动更新叠加易触顶，由部署者在面板调高阈值**），超限返回 429 + Retry-After 提示；**安装包下载为公开静态资源，不限流**（见 4.7）
- **真实客户端 IP 解析**（用于限流与日志）：环境变量 `TRUST_PROXY=auto|on|off`（默认 auto）——**auto**：当请求源地址为本机回环（127.0.0.1 反代）**或私有网段（10/8、172.16/12、192.168/16，覆盖容器化反代与内网反代）**时信任 X-Forwarded-For / X-Real-IP，其余来源（公网直连）忽略转发头防伪造；**on**：始终信任（前置反代多跳场景）；**off**：从不信任；**面板配置页展示当前生效策略**（见 3.4.8）；**边界说明（已知取舍）：auto 信任私有网段时，局域网直连模式的客户端可直接构造转发头伪造 IP，登录/下载限流可被绕过（防爆破/防滥用能力下降）；公网直连场景（源地址非私有网段）不受影响；对限流严格性有要求的直连部署请设 `TRUST_PROXY=off`**
- 安装包上传校验：仅大小 ≤300MB 限制（扩展名不设白名单，管理员自主控制）；部署文档中反代 `client_max_body_size` 同步调整

### 6.5 日志与隐私

- 日志记录中令牌查询参数一律脱敏为 `***`
- 下载失败记录失败原因（令牌无效 / 文件缺失 / 版本缺失 / 限流等），便于排查且不泄露敏感信息
- 5xx 内部错误默认脱敏返回通用错误；仅调试模式开启时返回详细信息（状态持久化，生产默认关闭）
- **实时日志流仅管理员可订阅**（暴露运行细节，不对外公开）
- **破坏性操作保护**：清空访问日志需二次确认；一键清空所有数据需**确认词 + 二次确认**（防误操作）

## 七、部署与运维

### 7.1 部署形态

- **Docker Compose 单服务**：`docker compose up -d` 一键启动；镜像多阶段构建（前端打包 → 后端编译 → 最小运行时），单镜像分发
- **两种接入方式（面向不同基础的用户）**：
  - **外部反代接入（推荐，公网部署）**：容器端口仅绑定 `127.0.0.1`，由部署者已有的反向代理承担 TLS 终止与域名接入（OIDC 回调要求 HTTPS 域名）
  - **局域网直连简化模式（0 基础/内网场景）**：docker-compose 直接映射端口（如 `8080:8080`），跳过外部反代；适用于内网/无域名场景（本地账号模式不依赖 HTTPS）；**注意：该模式下 Token 与密码经 HTTP 明文传输**，Setup/面板提供一次性风险提示，网络边界由部署者自行控制（防火墙/内网）；**验证码依赖外部网络，直连模式不建议启用**（见 3.2）
- 健康检查端点 `/health` 供反代/监控探活（**应急模式下返回 503 表示不可用，容器保持运行以提供应急页；compose 模板含 healthcheck 配置**，见 3.8）；**compose 模板约定：restart 策略用 `unless-stopped`，healthcheck 仅作状态展示不触发任何重启动作（应急模式 exit + 拉起循环为预期行为，不形成重启风暴，见 3.8）**
- 可选环境变量：**`APP_MODE=dev|prod`（启动时决定运行模式，默认 prod，修改需重启容器）**、**`RESET_ADMIN_PASSWORD`（非空时启动进入应急恢复模式重置管理员密码，见 3.8）**、**`LOG_LEVEL`（初始日志级别，默认 info；面板可运行时切换并持久化）**、**`TRUST_PROXY=auto|on|off`（真实客户端 IP 解析策略，默认 auto = 信任回环 + 私有网段来源转发头，见 6.4）**、监听端口（默认 8080）、日志格式（默认 console，可选 JSON）
- **部署向导**：README/部署指引提供完整向导（域名 + 反代 + HTTPS 配置示例，或局域网直连两种路径），并注明：OIDC 回调与验证码依赖公网可达（见 3.1）；**Setup 完成后请部署者本人立即注册/登录成为管理员**（先到先得，见 3.1）；**应急模式操作示例**（设置 `RESET_ADMIN_PASSWORD` → 重启 → 从运行日志获取一次性操作码 → 应急页操作 → 移除变量重启恢复正常服务；应急模式期间建议断开公网，见 3.8）

### 7.2 持久化与备份

- **单一数据卷**承载全部持久化数据：按模式分离的数据库文件（Dev/Prod 各一）+ 订阅/规则/自定义/分享版本文件 + `/public` 静态资源
- 备份 = 打包该卷（tar 即可）；恢复 = 解包到卷
- 数据库使用 WAL 模式；**WAL 下未 checkpoint 数据位于 -wal 文件，在线拷贝须连同 `-wal` 与 `-shm` 一起打包（或停止写入后拷贝，或使用 SQLite backup API）**，保证备份一致；Dev 与 Prod 数据库互不干扰，切换运行模式（重启后）不会交叉污染数据；**模式切换时数据不迁移**（Dev 定位临时调试）

### 7.3 可观测性

- 日志输出到 stdout（`docker logs` 查看），分级控制（debug 排查 / info 常规 / warn 精简）
- 支持 JSON 结构化输出，便于接入日志收集系统
- 访问日志与运行日志分离：业务下载记录在 Web UI「日志查看」中按日期查询

### 7.4 升级与维护

- 镜像自动构建发布（GitHub Actions 推送到容器仓库），`docker compose pull && up -d` 完成升级
- 数据卷不随容器重建丢失；无状态升级（业务配置全在数据库）；**数据库 schema 采用版本化迁移框架**（启动时按版本号迁移，重构首版即建立，支撑后续升级）
